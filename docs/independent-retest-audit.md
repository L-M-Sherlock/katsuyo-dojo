# 独立复测与调度验收

本方案于 2026-09-09 在复测接口实现前冻结。它从用户观察到的作答过程和产品目标设计，不以新增实现的分支或输出作为预期来源。执行种子见 `tests/fixtures/independent-retest-scenarios.json`。本文不把候选错因当成已证实的错误，也不将现有统计的 100% 解释为真实掌握概率。

## 原始证据与验收目标

只读检查 `katsuyo-dojo-progress-2026-09-09.json`：最新同题事件为第 17—20 条。原题「乗る → ている・否定」答 `のっていた`，原子无更新；随后 `のっている` 给 5 个知识点加分、`のっていない` 给 4 个知识点加分，最后结束拆步。该版本的 Profile 只有原子统计和作答日志，没有独立完成失败的持久状态。未来课程选择因此看不到这次整题独立失败。

完整验收须同时满足：

1. 真实的独立原题失败，无论能否定位原子，都持久留下完整题待复测状态。已经解释清楚某个原子，不能代替独立完整题复测。
2. 拆步、给定中间形式、给定词类、使用过提示、展示答案后的作答，记录其实际辅助条件；这些过程可以提供局部证据，但不能解除完整题待复测、增加完整独立覆盖或让整题应用因此重新达标。
3. 之后的另一道题，在不同词条、无提示、完整目标条件下正确，才可解除它实际覆盖的待复测项。同词换假名、换字体或换缩约写法不算换词；不同目标时态、不同应用不算同类复测。
4. 待复测必须进入出题，不得只在统计里挂一个永远遇不到的标记。正常可用题池下，在有限个后续原题内安排；上一轮最后一题错误、跳过拆步、重开专项、刷新页面、导入备份都不能绕开。
5. 同一道原题或同一次拆步的双击、Enter 重入和持久化重试只能产生一次成绩和一次状态变化；原子日志、独立记录、日统计和待复测应作为同一个保存快照提交。
6. 待复测影响“完整应用已达标/全路线已完成”的结论，但不回收已经开放的课程访问权，也不把所有共享基础规则无依据地判错。

## 复测粒度须显式定义

至少应区分：词类判断、基础目标形式、复合构式及其最终目标。`teiruNegative` 的失败不能被 `teiruPast`、单独 `negative` 或单独 `teiru` 的成功清掉。`tagaruPast` 的失败不能被 `taiPast` 清掉。双领域不能因复用了同一后缀而互相清掉待复测。

同一个 form 未必表示同一规则路径。`読む → 読んだ` 与 `書く → 書いた` 都是 past，音便不同；只做对后者不足以确认前者的规则。建议复测键包括实际规则路径，或至少把待检验的知识点约束放入候选筛选，绝不只按课程 id 清除。复合形式若早段已由原题明确验证，可把后续路径作为待检验范围，但需保存这个范围的证据来源，不能仅因早段“看起来接近”就缩小范围。

例外词只有一个可用词条时，不能伪造“换词成功”。保留待复测并说明题池限制；如产品将来决定同一例外词隔题复测，须明确这是另一种解除条件、独立列入日志和验收，不能悄悄降级。

## 独立反例矩阵

种子中的操作是产品层动作，并非生产函数名。`expect` 写的是状态约束；未来测试适配器必须把这些动作接到实际页面/状态变换，不能用同一函数重新计算预期。

| 分类 | 反例与必须发现的问题 |
| --- | --- |
| 原始案例 | 乗る teiruNegative 用 Past 替代；遅れる tagaruPast 去る接た，之后所有辅助题正确；都不能抹平整题失败 |
| 有归因也待测 | `読む → よみない` 有具体 stem 候选，后续局部答对仍不等于整题会独立完成 |
| 提示污染 | 提示展开再收起、给定词类后完整输入、正确答案曾展示，都不能冒充独立整题成功 |
| 换词身份 | 乗る/のる/ノル 是同一词条；缩约 `のってない` 不能冒充新词 |
| 目标冲突 | teiruPast 不清 teiruNegative；bare negative 不清 teiruNegative；taiPast 不清 tagaruPast；另一个课程做对共享 suffix 也不清 |
| 路径冲突 | 書いた 不清 読んだ 的拨音便失败；异词形容词/动词共享 suffix 不互清 |

| 调度 | 失败发生在第 1 题与第 12 题、全原子100%、专项切换、提前结束本轮、跳过拆步都能在约定范围安排复测 |
| 持久化 | 刷新、换日、导入导出、裁剪原始失败日志不丢待复测；已解决记录不因反复导入再次打开 |
| 旧版本 | 无日志无独立记录不可猜造历史失败；完整旧日志可恢复明确独立失败，但旧辅助正确不能作解除证据；无法追溯之处明确标为历史来源不明 |
| 并发/故障 | stale tab 对已更新 Profile 保存返回冲突；不能先在 UI 清待复测却保存失败；内存模式可导出；日统计、原子、独立状态快照一致 |

## 需要实现者给出的可验证接口

1. 独立表现的存储结构、复测键及辅助条件枚举。
2. 原题/辅助证据写入的纯函数，或可通过真实页面事件观测的等价入口。
3. 队列选择规则：何时到期，最多隔几题，多个待复测的排序，当前专项和不可出题项如何处理。
4. 一个可从 Profile 得到的状态摘要，覆盖原子/应用/课程/全路线判定。
5. 导入迁移的版本规则与日志重建边界。旧备份是否存在日志、日志有没有 hintUsed、是否完整，均必须影响可恢复性。

接口明确后，运行所有冻结种子，再补实际页面测试：通过点击/键盘完成错误原题、拆步、结束本轮、回自适应、刷新、导入，直接断言保存 Profile 与可见状态。单位测试绿灯不能替代整轮计划已正确接入的证明。

## 冻结时的执行状态

- 已完成当前文件和入口的只读审查。
- 已验证用户备份最新题的 4 条日志与上述基线一致。
- 独立种子已在生产复测接口实现前生成。
- 尚待复测接口落地后执行黑盒和页面集成；此时不宣称通过。

## 接口明确后的复核记录

原始 39 个种子及其 SHA256 保持不变：`1edab5313f3dce1745059d95c2c223b4a8809e15cd00ee1a8293ca6e62cc0221`。实现者明确了以下产品规则，验收补充记录于此，而非改写冻结输入：

- 普通复测按相同 form 与正确操作路径匹配，词条以领域、词类与归一化读音识别；至少隔两道其他原题。使用过提示、给定词类、给定中间形式、答案反馈后的结果不会解除。
- 为避免单词题池的例外永远无法恢复，完整词库确认某目标只有一个词条时，允许两道间隔原题并等待至少 24 小时后进行新的无帮助原题验证。这是显式的 `single-word-delayed` 策略，必须显示并记入日志。第 37 个冻结种子反对“暗中同词解除”的要求仍有效；不再把显式且满足延迟的单词复测视为失败。
- 新版 assessment 状态为导入权威；旧记录只恢复可证明的事件，辅助正确不作为独立成功回放。

`tests/independent-retest-state.test.mjs` 通过真实纯状态接口执行冻结场景中适用的子集：原题与辅助证据隔离、同词变体与不同规则路径、换词完整目标、两题间隔、辅助条件、首交幂等、重复失败、公平调度、筛选不能制造单词题池、显式 24 小时例外和 JSON 持久化。页面、迁移、日志、并发保存等场景仍须由相应集成测试验证；不能将纯状态子集的通过数说成全部 39 场景通过。

独立复核另外发现一个种子外边界：第 1 题失败，第 2 题同目标过早答对，第 3 题其他题，第 4 题又练同目标。若只从第 1 题计算间隔，第 4 题会被当作合格复测，忽略第 2 题刚提供的反馈。已追加独立回归测试，要求最近一次未合格的同目标练习也重新开始两题间隔。

该边界的独立红测试已经证明旧实现会过早解除。修复为从最近同目标展示计算间隔后，该测试通过。随后又独立检查了明确辅助操作更新曝光锚点：普通曝光更新器不增加原题数或成绩、不创建/解除待复测；事件重放幂等，旧事件不会把时间回拨；单词目标的 24 小时也从最近辅助曝光计算。专门的首次提示事件创建待复测的规则见下文。

进一步明确的计数口径：存在待复测时，即使没有手动提示，过早或同词的完整作答也是 `rehearsal`，不增加 `independentAttempts/independentCorrect`，而归入练习计数；它不是“使用过提示”的断言。`lastOutcome` 分别保存 `rehearsal-correct` 与 `rehearsal-incorrect`，真实独立首答及满足资格的复测才累计独立证据。

Profile 明确升级到 version 7，浏览器使用 `katsuyo-practice-profile-v7`。旧 v6/v5 只作为读取和迁移来源，以免旧标签页覆盖新评估状态。课程待复测按完整目标的所属课程显示；不把 `pending.kcIds` 中所有共享原子都改成未掌握。

## 实际页面发现的额外缺口

独立页面验收使用真实 `Page`、React 事件和浏览器存储适配器；仅附加词形标签的只读导出以辨认屏幕题目，不替换页面的选题、分析、评分、导入或保存逻辑。它发现并用红测试确认：已到期的复测题展开提示后，不提交而直接刷新，原页面只保存了组件内的提示状态，刷新便能把同一道受助题当作独立复测。

修复后提示展开立即保存独立事件，只有成功保存或保留在可导出的内存快照后才显示提示。已有待复测刷新曝光锚点；此前没有待复测的新题也建立 `hinted` 待复测，但原题数、独立尝试数和失败数仍为 0，失败时间为 null。收起提示不再写一个事件。两类“展开提示 → 不提交 → 刷新”均在实际页面回归中通过。

另一条新反例是：A 失败，B 使用提示或过早练习，隔两题后再次用 B 解除。最终资格要求同时避开失败词与最近受助/练习词，并持久保留 `lastPresentedWordKey`。对于「いい／かっこいい」这类真实双词题池，若二者都被排除，页面先明确安排不计独立掌握的巩固题 A；随后两道其他原题，再用 B 独立复测。实际页面已验证有限步可达，且单词例外仍使用 24 小时政策，不进入这种反复巩固。

失败数只表示实际未答对或揭晓，提示后答对与反馈后答对不捏造失败；若已有真实错误，保留原来的失败词、失败时间和失败次数，另外更新最近曝光。适配纯状态接口时，两处早期测试把“揭晓后能看到正确文本”写成 `reason: revealed, correct: true`，进而断言辅助正确加一；这与真实页面的 revealed 未答对结果矛盾，已纠正为 `correct: false`、辅助正确 0、失败 1。冻结种子从未要求揭晓计正确，其待复测与独立成绩预期均未改动。
