# 阶段优先补查

原题答案能精确匹配某个后续阶段的已支持错误模式时，先检查该阶段。选择顺序不产生知识点评分，也不会把跳过的前段当作已经答对。

例如「遅れる → たがる・过去形」答成「おくれたがた」，它同时符合“派生词误按一段动词变化”和“遗漏促音”的结果。新的拆步直接提供「遅れたがる」，先确认其词类，再在给定正确词类后检查过去变化。无需先重做「遅れる → 遅れたがる」，也无需再次提交同一个错误过去形才进入这两个检查。

## 判断依据与范围

当前接入普通五段／一段的る结尾派生词过去变化冲突：たがる、ておる、てあげる、てくれる、ている、てみる、すぎる，以及受身、可能、使役、使役受身的过去形式。

1. 从正确变化路径生成中间形式及允许的变体。
2. 检查用户的完整输入是否精确等于给定中间形式去掉末尾る后，使用另一词类的过去接续所产生的字符串。固定前部必须完整匹配；汉字、假名和片假名按现有规则归一化。
3. 多个阶段上下文同时匹配时，保留完整检查。
4. 输入同时属于同词的另一种合法形式时，也保留完整检查。例如「書いていった」可能来自「ていく」的过去形，不能只按「ている」多写促音来选择后段检查。
5. 只有一个符合约束的候选阶段时，直接生成不计分的派生词类选择，以及给定词类后的过去变化题。

「おこれたがた」等前部与词尾同时损坏的答案不触发该优先顺序。其他未支持的错误仍使用已有的完整拆步或基本操作补查。正确答案、明确的具体归因、笔误重试和精确停在中间形式的处理保持各自的优先级。

这是一种有边界、可重复验证的补查选择，不是对学习者真实错因的证明。入口在 `unifiedDiagnosticSteps`；`probe-routing.mjs` 只生成补查顺序，`diagnostic-feedback.mjs` 提供相应说明。

## 与计分的关系

- 原题保持错误结果，`diagnosis.kcId` 和已确认知识点保持原有判断；优先级本身不增加正负证据。
- 派生词类选择仍是诊断性问题，不计入原词分类或整体应用掌握度。
- 后续过去变化只评估实际需要的基础规则。原词分类、前段构成和整体应用不在该步范围内。
- 如果同一知识点也出现在被跳过的前段，仍须保留它在后段的实际评估机会。例如「待つ → ておる・过去」前后都涉及促音便；没有检查前段，就不能假设促音便已经评估过。后段会评估一次，队列继续防止重复计分。
- 后段仍无法归因时，进入有限的基本操作检查；不会反复生成相同的词类问题。

原题日志中的 `diagnosis.resolution` 为 `stage-priority`，说明为何优先检查；原题 `changes` 不会因此增加。后续日志记录实际作答和实际写入。历史日志保持原来的步骤顺序，不做回写。

## 自动检查

`tests/probe-routing.test.mjs` 固定真实例子、跨表达输入、汉字／假名变体、前部损坏、其他合法表达冲突和共享规则的范围。它还连续运行答对、重犯原错、输入无法识别三种队列，检查有限结束和重复计分。

`scripts/lib/probe-routing-cases.mjs` 独立声明错误输入与应有的顺序，不调用生产选择器或归因函数；生成的 `priority-stage`、`priority-guard` 模式并入全量归因审计。`tests/probe-routing-contracts.test.mjs` 会故意恢复从头拆步、伪造扣分或前段正证、删掉共享规则、给保护输入提前定位，确认这些退化能使审计失败。

网页交互测试检查从原题直接进入两步补查、正确与错误的后续判分、日志、Enter 和完成后的说明。键盘监听在整个页面生命周期保持连接，通过布局阶段提交最新回调，避免刚出现反馈时读到上一状态。
