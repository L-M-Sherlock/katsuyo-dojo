# Furifont 振假名显示

本项目沿用 [bunpo-dojo](https://github.com/L-M-Sherlock/bunpo-dojo/blob/main/docs/furifont-migration.md) 的迁移方式：使用本站原有正文和读音生成定制字体，不让上游词典重新判断读音。原有词形、例句、读音和英语覆盖层仍是内容来源；字体只改变显示。

## 当前构建

当前 17,138 张用法卡，以及词库、合法答案变体、推导和拆步输出，共形成 59,784 个不同的正文／读音配对。59,243 个可直接对齐，539 个根据已有汉字组读音唯一对齐，另外两个使用精确布局；当前语料没有未对齐的片段。生成器将结构上不支持的词类／形式组合单独记录，不将它们当作出题许可。

三套字体共 1,623,540 字节：

|用途|字体|字节|汉字组／读音配对|注音比例|
|---|---|---:|---:|---:|
|用法卡、拆步、日志和复测|Sans|643,284|5,518|0.5|
|答后推导与词形说明|Serif|826,536|5,518|0.4|
|题目大字|Display|153,720|231|0.18|

Sans 使用固定版本的 Source Han Sans JP VF；Serif 与 Display 使用固定版本的 Noto Serif JP VF。Display 只包含词形子集，保持大字题目的较小注音。每套字体按实际需要加载并共享缓存。

构建审计检查了最终 WOFF2 的 45,068 次字形选择和 74,357 个字形组件，并验证各字重的注音外溢。固定日期重复构建时，三套字体和完整清单、审计收据逐字节相同。

## 渲染约定

- 题目、拆步、推导、日志、复测记录和用法卡共用振假名渲染组件。
- 只有精确匹配 `(text, reading)` 的片段才使用字体清单中的 `salt` 选择器。选择器写入 CSS，不向原文插入 variation selector 或私有区字符。
- 在指定字体成功加载前，以及字体加载失败或映射缺失时，继续显示原生 HTML ruby。加载字体不会阻塞作答或重新抽题。
- 不带注音的文字继续使用原有日语字体。字体字形中的假名与汉字使用相同颜色；原生 ruby 后备仍可独立设置注音颜色。
- 注音片段内部保持完整，在片段之间换行。只按最终字体实测的左右外溢预留空间，避免给所有词统一加宽。
- 学习档案、答案匹配、题目 ID、掌握度和复测队列均不存储字体状态。

## 维护与验证

生成工具固定版本，基底字体固定提交和 SHA-256。生成产物包括本站字体、精确配对清单和审计收据；授权与来源说明保存在 `public/fonts/furifont/`。

`app/data/furifont-manifest.json` 保存完整构建与审计信息，浏览器只导入 `furifont-runtime.json` 的精简投影。运行数据包含字体地址、哈希、字重及每个片段的选择器和外溢值，不携带审计专用字形元数据。精简后约 539 KB，gzip 约 67 KB；审计会验证它与完整清单严格一致。

```sh
npm ci
npm run build:furifont
npm run audit:furifont
npm test
npm run typecheck
npm run lint
npm run build
```

新增或修订含汉字的正文、读音或动态构形后，重新生成字体与清单。审计必须将当前语料与清单双向比对，并用 HarfBuzz 检查最终 WOFF2 实际选择的字形、读音组件、可变字重和注音外溢。只有清单中“存在”一项，不能证明字体正确。

浏览器检查需覆盖中文与英语入口、字体加载成功与失败、多音字、熟字训、送假名变化、答前挖空、答后补全、拆步与窄屏换行。去除原生 `rt` 后的正文必须保持原样，字体切换不得改变答案草稿和当前题目。

实现参考 [Furifont v0.1.2](https://github.com/antfu/furifont/releases/tag/v0.1.2) 与该版本的[设计说明](https://github.com/antfu/furifont/blob/v0.1.2/docs/design.md)。项目使用本站读音构建，不引入 Furifont 上游词典的自动推断结果。
