# 验证与发布

`CI` 在 main 推送和 PR 上运行单元测试、知识模型检查、全对及混合学习模拟、类型检查、lint 和构建。main 的成功构建上传为 Pages 产物，随后调用可复用的 `pages.yml` 部署；部署不重新安装依赖或运行检查，PR 不发布。验证失败不会启动部署，新的同分支提交会取消旧 CI。

`scripts/ci-audit-scope.mjs` 根据 push 的 before/after 或 PR 的 base/head 比较改动，包括删除文件。仅选课、题目轮换、文案及文档等改动不执行额外大型审计；归因、活用、计分、词库、相关审计工具、页面逻辑或依赖变化执行代表性归因及路径审计。未知的规则文件也触发检查；历史不可读取时默认运行代表性审计，不能默默跳过。

代表性归因审计使用 `--representatives`，按形式、词类、词尾和特殊变化结构选择词条，仍检查全部形式、评分契约与失败结果。报告明确标为 `structural-representatives`，不宣称全词库覆盖。其未生成的模式不作为全量覆盖失败；完整模式覆盖仍由全量任务检查。

需要完整词库覆盖时，手动运行 `Full diagnosis audit`，它执行两套原有全量并行审计并保存报告。没有定时触发；普通发布无需等待此任务。

所有策略只改变工程验证流程，不改变学习数据、计分或课程内容。
