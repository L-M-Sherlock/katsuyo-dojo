接入内容位于 `app/lib/usage-cards/actions-generated.mjs`。当前动作阶段覆盖 6,852／7,004 配对，全站内容目录有 16,291 张卡片。旧 9,598 张卡的 ID、顺序与对象内容逐项保持不变，历史 SHA-256 为 `5f7f9dcef365905069a2d258a7581b5e3974044caf13bda7b74d959e40fdcfcf`。

## 语言审核

作者与审核者分批交接，源稿保持 `draft`，审核记录逐卡保存实际完整句、决定、具体理由和纯卡对象 SHA-256；协调者核对后将通过卡标记为 `approved` 接入。用户指定的长期配置为作者 `gpt-6-astra low`，审核者 `gpt-6-astra medium`。

本轮实际返修包括授受方向、自动词与他动词混淆、完成否定被译成完全没做、てある准备结果不足、ていく／てくる时空视点冲突、过去译成将来、槽外重复答案、中文字段占位、以及汉字读法和注音分界。独立审核也曾错误使用通用理由或冻结旧报告；这些决定被撤销重审，不能用文件存在或结构通过替代语言判断。

未决裁定中有 39 项通过重新选择具体语境、纠正译文或澄清课程用义而解决；复审又新增了两项疑点。当前 [152 项清单](usage-card-actions-pending.md)保留每张原句、场景、译文和具体原因。`てしまう` 否定的审核规则已改为开放语境判断，不再硬性要求“全部做完”；这些配对仍需按新规则逐句重审。它们没有被替换成其他动词来凑数，也没有混入网站卡片；未通过本次用例审核不代表在所有日语语境中都不成立。

## 验收与溯源

[审核清单](usage-card-actions-review.json)保存原缺口校验和、旧卡基线、批准集合、批次信息、最终对象校验和与未决集合。验收检查当前有效配对恰好等于已覆盖配对与明确未决配对的并集，两者不相交；同形式其他词不能填补缺少的词义配对。

临时流水线为每次最终交付保存独立版本快照，并绑定其内容校验和。候选构建从经过校验的快照字节读取卡片，拒绝冻结后漂移和过期审核句。失败命令不会被当作新产物，交付工具也不能自动批准语言内容。

`npm run audit:usage` 输出动作阶段的已覆盖、有效和缺少配对，同时继续严格检查此前已完整覆盖的阶段。相关内容测试核对新卡对象、历史卡不变性、卡片与审核清单一致性以及正面隐藏答案行为。构建和类型检查通过；发布状态应以实际部署结果为准，不能将工作区接入称为已上线。

本次本地验收：全套 901 项测试通过；Windows 上用 Git Bash 执行 CI 门禁测试，避免误调用 WSL 启动器。全对及混合学习模拟的各条路线均完成；`audit:usage`、类型检查、lint、生产构建通过。真实页面验证了整词挖空、答后完整句、译文和注音。以上不改变未决配对的状态，也不代表动作阶段已经逐词全部覆盖。
