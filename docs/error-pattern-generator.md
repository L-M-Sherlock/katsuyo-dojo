# 错误模式生成与归因覆盖审计

将实际反馈变成可重复生成的输入族，而不是每遇到一个词就新增一条手写用例。网页与审计通过 `app/lib/answer-analysis.mjs` 使用同一个判题入口，按“接受变体 → 明确诊断 → 笔误重试 → 保守拆步”的顺序处理。

当前完整方案见[诊断路径与自动检查](diagnostic-paths.md)。本文记录现有 52 类候选模式及其逐轮验证；独立操作生成器覆盖全部 131 种形式、合法变体、基本操作和多处错误，并检查未知输入的补查流程。两层审计均为 CI 和发布必过项。下文带日期的用例数是历史快照，当前结果以各自生成的报告为准。

## 已出现的问题

| 模式 | 实际例子 | 应检查的行为 |
|---|---|---|
| 复合表达末尾混淆 | 始める → てあげる过去，答はじめてあげない | 区分共享规则与场景应用，不能仅凭整题错误随意扣重点原子 |
| 不变词汇部分笔误 | 楽しむ → てあげる否定过去，答なのしんであげなかった | 提示重输；本次不写入答题或知识点统计 |
| 多个规则混用 | 頼む → たい过去，答たのんだいた | 保守处理并拆步，不能用字符串相似度猜测失败原子 |
| 漏词汇字符／长音 | 申し込む → たい过去，答もしこみたかった | 保留足够完整词汇、词尾全对且只有一种修正时提示重输；短词或跨边界歧义保守处理 |
| 接续漏写 | 早い → 否定，答はやく | 确认く形，否定接续记错；不额外确认分类或副词应用 |
| 基础形式混淆 | 大きい → 过去，答おおきくない | 提示写成否定形，只更新本题要求的过去接续 |
| 完成前置步骤但漏后续 | 遠い → 否定过去，答とおくない | 确认否定步骤，只检查剩余过去变化，前置证据不重复写入 |
| 完成词干但漏接续 | 書く → ます，答書き | 确认五段い段词干，只记错ます接续 |
| 接续内部漏末字 | 書く → ます，答書きま | 完整词干和部分接续均可见，定位到ます接续；任意截断词根不适用 |
| 基础词尾漏末字 | 読む → 过去，答読ん | 过去接续记错，确认可见的撥音便；末字缺失不能同时确认浊化 |
| 只漏禁止接续 | 書く → 禁止，答書く | 本题只需添加な，禁止接续记错；照抄原词不获得分类或词干正证 |
| 只漏邀请疑问词尾 | 書く → ませんか，答書きません | 邀请接续记错，只确认连用词干；不额外确认ます接续 |
| 已完成部分、剩余多条规则 | 書く → なくてもいい，答書かない | 确认否定形，从已提供的否定形继续拆步，不武断区分く形、て形与表达应用 |
| 否定接续停在く形 | 書く → なくて，答書かなく | 确认否定与く形，剩余て形规则和なくて应用继续拆步；提供く形后仍原样回答才定位て形规则 |
| 目标形式与词类误用同形 | 待つ → て形，答待て | 可能是命令形，也可能误套一段词类；不在两种归因中任意选择 |

还生成音便遗漏、浊化遗漏、いい误套常规词干、其他词类误用、词尾删除、正确答案与口语变体、格式归一化，以及拆步上下文中的正确／错误输入。原有 32 类模式之外，通用错误语法新增 13 类，受身阶段与细分拆步增加 3 类，派生词诊断性分类增加 1 类，混合过去补查与保护增加 2 类，同一接续的两处不连续遗漏增加 1 类，合计 52 类。每类在适用词、形式、汉字／假名、变体、整题／拆步上下文中展开。计分检查覆盖提示和未提示两种状态。

`common-suffix-disjoint` 枚举单一接续内所有不相邻的两个字符位置并删除，保留完整前部。例如「閉めさせられる → 閉めせれる」，差异都在使役受身接续，要求仅更新该接续知识点；不能以“有补查步骤”为通过依据。若结果是合法变体则排除，匹配已有词类误用或其他竞争解释时保留原处理。词干也损坏的输入不能套用此合同。

## 按操作展开的常见错误矩阵

`scripts/lib/common-error-patterns.mjs` 将错误生成拆成“正确词根或给定中间形式 + 一个出错操作”。词汇不变部分、词干变化、音便主体、末尾接续分别有明确边界。生成器逐位置枚举适用的局部变化，不随机截取几条字符串，也不把两个错误操作的笛卡尔积都当作单一成因。

| 操作 | 生成范围 | 独立归因约定 |
|---|---|---|
| 词干错行 | 五段相同末音的其他 a/i/u/e/o 行，另测う→あ；する／来る的已列出词干错选 | 目标词干原子；する／来る按基础接续与连用词干各自的知识模型归属 |
| 未去词尾 | 一段保留る后接完整目标接续；な形容词在完整词根后多保留な／だ | 一段去る，或本题な形容词目标接续 |
| 音便错类 | っ／ん／い／し／つ／空音便主体，保留正确末尾た／だ／て／で及后续表达 | 对应音便原子；行く特例、す→し单列；清浊音同时改变不据此归因 |
| 连续片段遗漏 | 接续任意 `[start,end)` 片段，包括首部、内部、末尾和整个接续 | 该接续原子；已有中间态或末字遗漏的前置正证继续保留 |
| 清浊音替换 | か↔が等对应音，は／ば／ぱ等组三向互换，每次只变一处 | 该接续原子 |
| 大小假名 | 形容词接续的小假名对应替换；动词接续的っ↔つ | 该接续原子 |
| 多写促音 | 动词非音便边界的接续内每个位置插入っ | 该接续原子；五段过去／て形的音便边界不作此推断 |
| 连续片段重复 | 接续任意连续片段相邻重复一次，含单字和整个接续 | 该接续原子；例如ではない→ではないない，而ないない缺少では，仍是多处变化 |
| 相邻顺序颠倒 | 接续内相邻两个不同字符交换一次 | 该接续原子；不跨越词干和接续边界 |
| 词根内部多字／颠倒 | 固定词根至少两字；内部重复首字、相邻不同同文字体系字符交换 | 所有接受答案合并后只有一个安全纠正目标时提示重输；活用部分必须完全正确 |
| 复合末操作变异 | 从正确第一步生成末尾基本规则变异，每种操作至多一个代表输入 | 整题不能区分共享规则与表达应用时保守拆步；提供正确基础形式后的步骤按当前原子检查 |
| 多错保护 | 在活用变异之外再损坏词根，及已有自然语言多错反例 | 未归因，不增加无证据的掌握度变更 |

基础动词范围为否定、过去、て、ます、なさい、可能、受身、使役、使役受身、命令、意志、ば和禁止；追加表达覆盖たい、ながら、つつ、すぎる、たがる，以及てあげる、てもらう、てくれる、てください、ている／てる、てある、ておる、てほしい、ても、ては、てもいい、てみる、ていく／てく、てくる、てしまう、ておく。完整て形前缀仍可见的接受变体也展开。改变连接边界的じゃう／どく等缩约继续使用已有专门模式，不强套完整て形追加规则。

另外覆盖 15 个可以明确分离最后单一接续的目标：ないで、ないでください、なくてもいい、なくてはいけない、なければならない、ないといけない、たら、たり、たって、ようとする、ずに、ませんか，以及礼貌过去、否定、否定过去。例如「書かないでくさい」已经完成ないで，只有ください内部漏字；「書きましだ」定位礼貌过去规则。整个前置形式必须完整。礼貌复合若只写出「書き」，仍需继续检查ます与礼貌变化两个原子，不能因为生成器知道删去了哪个片段就假定学习者只错了最后一个原子。

形容词范围覆盖い形容词过去、否定、て形、ば形、副词形，以及な形容词连体、判断、否定、过去、て形、条件和副词形式。い形容词否定／て形将く词干与后续ない／て分别变异：しろぐない属于く词干，しろくいな属于否定接续。いい只在よ词干已正确表现时扩展局部接续变异。否定过去整题涉及多个原子，继续使用已有明确反例、正确中间态和拆步契约，不把整个くなかった视为一个原子。

`tests/common-error-patterns.test.mjs` 有独立适用性表，逐个检查 51 种基础／追加动词形式在五段、一段、する、来る及汉字／假名书写上是否生成相应模式，另检查形容词的常规、いい例外和な类目标。五段命令形只有 e 行词干，没有可变异的追加接续，明确列为不适用。该检查能发现“某个模式在别的形式出现过，但本目标没有生成”的遗漏。归因验证还覆盖整题与默认／动态拆步；逐目标的生成情况和行为回归应与全局总数一起阅读。

通用生成器保留同一上下文的已有独立契约优先级。例如食べった符合旧词类误用规则，不能由于新增“多写促音”操作就改扣过去接续。拆步中，候选解释涉及当前步骤外的词类或已完成原子时，也不能通过过滤这些候选来伪造唯一归因。所有候选先进行成因碰撞检查，再判断本步允许更新的原子。给定基础形式不一致的短使役或缩约变体不会被重新当作长基础形式继续变异。

词汇笔误的唯一纠正目标同时考虑替换、删除、插入和颠倒，并合并所有汉字／假名及口语变体；旧漏字模式也使用这套独立判断。例如「調べる」可能形的「しべられる」，既可能是「しらべられる」漏ら，也可能是「しらべれる」交换ら／べ，不能当成只有一个修正答案的笔误重试。新增操作揭示这种歧义后，旧的单操作笔误预期必须一起修正。

### 本轮验证（2026-09-08）

最终按互斥形式分成四组执行全词库审计，共 **2,622,528 条用例、2,545,921 个不同输入上下文、45 类模式、131 种目标形式**。其中 **2,452,936 条明确约定全部通过**，归因回归、安全违规和模式／形式漏生成均为 0。新增通用模式包含 1,855,982 条明确约定，其中既有精确归因，也有应当保持未知或提示重试的反例；不能把这一总数理解为每条都应扣某个知识点。

仍有 169,592 条探索用例，报告中 22,529 条未识别、45,807 条仅拆步回退，其他探索结果也不自动视为已证明正确。与前一轮 758,658 条基线相比，末字删除从只取标准答案扩至所有接受变体，既有模式增加 7,888 条输入，因此新增探索缺口与拆步不能直接当作能力退化；同范围的词根遗漏未识别数减少 17 条。逐模式对比见 `outputs/diagnosis-audit/report.md`。

审计还推动修正了两处合同与计分问题：「しべられる」可由「しらべられる」漏字或「しらべれる」颠倒得到，联合所有编辑后不再满足唯一修正条件；礼貌形混淆只确认实际可见的词干与ます接续，不给分类、启发式或覆盖 facet 加分。长使役与ていく拆步也同步限制实际可继续使用的给定形式，避免把短形式套进另一种词类。

项目单元／交互测试 299 项、并行审计合并测试 5 项全部通过；类型检查、lint、知识模型审计和构建通过。本轮结果覆盖上述有限错误语法，不能证明全部自然错误均可归因。

## 独立预期与覆盖边界

生成器入口位于 `scripts/lib/error-patterns.mjs`，通用局部操作由 `scripts/lib/common-error-patterns.mjs` 提供。两者不调用归因函数，也不读取归因候选列表。预期失败原子、应确认步骤和剩余步骤要求，由独立的模式表指定。新通用模块不接收实际判题结果；已有契约继承、正确变体排除、成因碰撞和笔误唯一纠正判断都在调用分析器之前完成。

正确答案和接受变体由活用引擎提供，因此这套审计不能独立证明活用引擎本身的语言学正确性；引擎另有单元测试。真实操作序列只用于生成“停在中间步骤”的候选；明确预期由另一份 `stopPolicies` / `baseEvidence` 语义表规定，不读取操作序列的知识点标签，也不读取诊断结果。

同一个错误字符串可能有多个成因。故模式分为：

- **contract（明确约定）**：可以定义可靠的行为，包括应精确归因、应确认前置步骤、应重输，以及应保守处理。违反约定会失败。
- **explore（探索）**：生成有意义的候选错误，但尚未规定唯一归因。报告分别标为已识别、提示重试、仅有拆步回退、未识别。已识别不等于语义归因已被证明正确；未识别也不等于可以直接扣某个原子。

同一输入族可以同时包含两种级别，报告标为 **mixed**，并在 JSON 中分别记录 `contractCases` 和 `exploratoryCases`。例如词汇漏字中，原固定部分至少三个字符、删除后仍保留两个字符、所有删除解释都位于词汇内部、且只有一个正确修正目标的子集必须触发重输；其余候选仍保持探索。不能靠把整个输入族改称“已覆盖”提高指标。

任何模式都会检查错误接受、知识点越界等基本安全约束。对实际错误证据，额外验证同一原子只写入一次、无关记录不变、提示权重保留、部分正确不计整题速度。动态拆步另外检查标签与实际活用目标一致、步骤有可评估知识点、已经确认的原子不再出现，并生成正确答案、未知输入、原地未继续的输入。网页交互测试继续负责每日题数、连对、保存冲突及 Enter 导航，生成审计不宣称替代浏览器测试。

生成前会排除“错误形式恰好也是本题接受变体”的同形情况，例如一段动词的可能形与受身形可能重合。相同模式与上下文的重复输入去重；同一字符串跨模式仍可能出现，因此同时报告用例数和不同输入上下文数。

分类选择题没有自由文本输入，不在本次 131 种活用形式的输入审计中。

## 使用

全量审计（四组互斥的目标形式并行运行，结果合并到同一份报告）：

```bash
npm run audit:diagnosis:parallel
```

单进程运行及带筛选参数的审计仍使用 `npm run audit:diagnosis`。并行合并会检查目标形式不重叠、全形式齐全、各模式计数一致；缺失分片或执行失败不会复用旧结果。CI 与发布检查默认使用并行全量审计。

默认产物（不提交到仓库）：

- `outputs/diagnosis-audit/report.md`：按模式汇总与示例。
- `outputs/diagnosis-audit/summary.json`：模式、领域、词类、目标形式、整题／拆步和逐知识点统计。
- `outputs/diagnosis-audit/findings.jsonl`：所有回归、未识别和仅拆步回退案例，包含输入、稳定 ID、预期与实际行为。

复现一条发现：

```bash
npm run audit:diagnosis -- --replay 7755bc04434dd278daa6
```

默认读取已有发现以定位题目，输出到独立的 `outputs/diagnosis-replay/`，不会覆盖全量报告。若已有报告中没有该 ID，则重新生成查找。ID 不依赖课程位置或运行时间。

只检查一个模式、导出全部样本或要求探索缺口也阻断：

```bash
npm run audit:diagnosis -- --pattern negative-intermediate
npm run audit:diagnosis -- --cases --output outputs/diagnosis-all
npm run audit:diagnosis -- --strict
```

按目标形式运行专项审计，保留全部适用词、模式与拆步上下文：

```bash
npm run audit:diagnosis -- --forms naideKudasai,masuPast,masuNegativePast
```

`--forms` 接受逗号分隔的目标 ID；未知或空的目标会报错。默认写入独立的 `outputs/diagnosis-forms/`，不覆盖全量报告。它也可与 `--pattern` 组合，检查某一形式是否实际生成、正确处理某一错误族。专项比较需使用相同形式集合与模式筛选。

保存一轮摘要后比较改进效果：

```bash
cp outputs/diagnosis-audit/summary.json /tmp/diagnosis-baseline.json
npm run audit:diagnosis -- --compare /tmp/diagnosis-baseline.json
```

报告同时列出每个模式的用例数、未识别、拆步回退和回归数量的前后变化；既有模式单独聚合，新增模式另作标记。对比范围必须相同；生成器新增样本会改变分母，不能把样本数量变化当作诊断能力变化。

默认退出码：明确约定失败、安全违规、分析器异常或模式／形式漏生成时为 1。探索未识别及仅拆步回退会列入报告，但不阻断。`--strict` 将这两类也视为失败，因此在当前仍有探索缺口的版本上预期返回 1。

CI 与 Pages 发布校验会执行全量默认审计并保留报告产物。后续新增一个语义上能可靠定位的规则时，应将相应探索模式或明确适用子集升级为 contract，再补充固定反例，以防止误归因。

## 怎样判断下一步补什么

优先看“完整而可识别的答案结构”，例如ます题答書き、ます题答書かない，以及误用词类后使用了口语变体。其次看能识别完整前置步骤、却仍从第一步重新拆解的复合题。

词汇漏字、词尾任意截断和多错混合不应直接一律加上扣分规则。生成器的作用是把候选和现有行为集中呈现，再把具有明确证据的子类变成可执行约定。

## 白い → しろいた：补足生成操作的盲区

上一轮中，白い的过去形只有 25 条生成输入，没有包含「しろいた」或「白いた」。删除正确答案的末字只会得到「しろかっ」，切换到另一种合法形式只会得到「しろくない」等；两者都不能自动生成“保留原形い后添加た”的错误。因此，全量用例通过不能证明尚未设计的错误操作也已覆盖。

| 模式 | 生成方式 | 明确约定 |
|---|---|---|
| `i-ending-retained` | 原形直接添加完整后缀：白いかった、白いくない、白いければ | 过去与条件分别定位相应接续；く形相关形式定位 `adj.stem.i-ku` |
| `i-bare-ending` | 原形直接添加简化后缀：白いた、白いない、白いて、白いば | 与完整后缀模式使用同一独立原子映射，不凭末尾相似度猜测 |
| `i-affix-guard` | 在以上输入中再损坏词根、重复词尾，或混合否定过去的阶段 | 必须保守，不通过一个相似后缀接受错误词根或混合错误 |

## 快適 → かいてきたっだ：固定过去接续内部的清浊音错误

「快適だった」的词汇部分「かいてき」正确，但「だった」被写成「たっだ」。此前的末字删除、完整形式替换与动词音便模式都不会产生这类输入，因此新增以下独立操作：

| 模式 | 生成方式 | 明确约定 |
|---|---|---|
| `na-past-voicing` | 原生な形容词完整词干后添加「たっだ／たった／だっだ」 | 仅在な形容词过去题定位 `adj.suffix.na-past`；不确认分类或其他知识点 |
| `na-past-voicing-guard` | 同时损坏词根、重复或追加词尾；在其他な形容词目标及原生い形容词过去题中使用同样错误尾 | 不因词尾相似而套用过去归因；保持无扣分、无正证，允许既有复合题拆步 |

## 幸せ → しあわせない：接续中任意连续片段的遗漏

原有 `ending-deletion` 只删除正确答案的最后一个字符，不能产生「幸せではない → 幸せない」这样漏掉接续开头两个字符的输入。此次将原生な形容词接续的删除操作系统展开，而不是为「幸せない」另列一个特例。

`na-suffix-span-omission` 从每个正确答案与接受变体中分离完整词干和接续，对接续按字符枚举所有非空连续删除区间 `[start, end)`，覆盖开头、中间、末尾和整个接续。例如「だった」会产生「った／た／空串／だた／だ／だっ」六种结果。词干始终保持完整；汉字与假名均生成，跨变体得到的相同输入去重。

预期由生成器自身的静态简单形式表规定，不读取生产候选或操作序列的知识点标签：连体、终止、否定、过去、て形、条件、副词各只定位本题对应的 `adj.suffix.na-*`，正证始终为空。整个接续删光只剩原词时，也只是判断本题要求的接续尚未完成，不宣称裸词干在日常对话中不合法。

否定过去包含多个变化，因此相同删除操作在 `adjectiveNaNegativePast` 下标为探索。它不会因为输入长得像某个后缀，就被生成器预先指定到否定、过去或复合应用中的一个原子。报告分别展示此模式的明确约定与探索数量。

合法答案碰撞必须先排除。「ではない」删除「は」得到「でない」，「ならば」删除「ば」得到「なら」；它们不能作为错误样例。「でない／でなかった」也纳入对应否定目标的接受变体与正确对照。国際交流基金的文法资料明确使用「べんりでない」作为な形容词否定形式。[JF《まるごと A2/B1 文法》](https://www.fundacionjapon.es/userfiles/file/Curso%20JFS/MarugotoGramaticaA2-B1_JP.pdf)

「でなかった」的依据包括国语研究所资料中的形容动词否定过去形式「楽でなかっただろう」；接受变体同时适用于原题、完整否定中间形式识别和后续拆步。[国语研《方言文法調査ガイドブック２》，第 149 页](https://www2.ninjal.ac.jp/takoni/DGG/DGG2.pdf#page=155)

`na-suffix-span-guard` 在非接受的删除结果上继续损坏词根，或添加固定的「ないない」。通用矩阵补全后，生成器会先检查结果是否恰好也是某个完整合法接续的一次连续片段重复：例如「幸せでないない」是「でない」的ない重复，应定位否定接续；「幸せないない」才是遗漏では之后又重复ない，继续保持无归因、无正证。这种检查使用独立字符串操作表，不读取实际分析结果。不能用任意追加字符制作保护用例，因为它可能复原正确答案或形成另一个可唯一归因的错误。い形容词和动词不进入这一专门删除模式，既有过去接续清浊音模式继续保留。

固定测试检查「しあわせない／しあわせでい／しあわせでは／しあわせ」四种删除位置、「だった」的全部六个区间结果、全部七类简单接续、合法变体碰撞、な形容词末尾为い的例外词、损坏词根和多错保护。此次系统覆盖的是**原生な形容词接续的连续片段删除**，不代表替换、重复、调序、跨步骤混用或全部自然错误已经覆盖。

本轮全词库专项覆盖 40 个な形容词：3,239 条简单接续遗漏约定和 13,114 条保护约定全部通过；另有 3,318 条否定过去探索样例，均继续拆步。全量审计共 758,658 条用例、737,158 个不同输入上下文、32 类模式、131 种目标形式；595,282 条明确约定全部通过，回归、安全违规与形式漏生成均为 0。补收合法变体使既有模式新增 2,844 条用例，其探索未识别及拆步回退数量不变；新模式的 3,318 条探索拆步单独计入，总拆步回退为 40,760。网页与单元测试 266 项通过，类型检查、lint、知识模型审计及构建通过。

| 普通五段る尾 | `tagaruPast`、`teoruPast` |
| 一段 | `teageruPast`、`tekureruPast`、`teiruPast`、`temiruPast`、`sugiruPast`、`passivePast`、`potentialPast`、`causativePast`、`causativePassivePast` |

要求整个派生词词根保持正确，并精确匹配五段る尾漏「っ」或一段误加「っ」的形状。规则作用于实际提供的派生词及接受变体；原词是一段或不规则动词，不会改变「たがる」产物的五段类别。`てもらう／てしまう` 的う尾不能仅因旧反事实函数也能套入一段公式，就制造真实的一段类别解释；它们不进入本次阶段规则。`ある／いく／くる` 等特殊输出也保留原有处理。如果前置步骤已经评估促音，使当前步骤不再包含 `onbin.sokuon`，也不能从范围外加回候选或探针。

生成器在既有默认与动态拆步中加强阶段合同，再生成后续上下文，检查汉字、假名、接受变体、类别选择以及给定类别后的全部适用通用错误。多错和词根损坏仍保持保护。审计只允许同时具备 `kind: "classification"`、`diagnosticOnly: true`、明确 `expectedClass`、完整选项以及空 `kcIds` 的分类探针不计分；普通空知识点步骤仍视为错误。给定类别后的过去探针只能评估原步骤中的共享词干、促音和过去接续，不得给原词类别、应用或覆盖原子信用。

缩约也要按实际给定的词形保护边界。例如「食べてるた」是给定「食べてる」后未去る，不能因为它与长式「食べていた」只差一个字符，就当作词根输入失误而提示重试；如果去る已经在前置步骤评估，本步仍不重复扣分。

本次专项使用独立目录，包含 11 个受影响目标的所有适用旧、新模式：

```sh

```

## 閉めたがる → しまたがだ：混合差异也能安排独立补查

「しまたがだ」同时改动了原词前部「しめ」和过去变化末尾。它不符合此前“完整给定前部后只漏／多っ”的严格阶段合同，也不能当作单纯词汇笔误。新合同将这种可观察差异记录为 `review`，与已经定位阶段的 `stage` 分开：原次作答不扣分、不加分，但必须提供后续类别确认和给定类别后的过去变化练习。只返回未知错误会触发 `missing-review` 回归。

新增 `common-mixed-past-review` 与 `common-mixed-past-guard`，仍限定在上一节的 11 个普通る尾派生过去目标，以及原步骤同时保有应用与相应共享规则的上下文。独立尾部语法由 `空串／っ／つ／ん／い／し／り／る` 与 `た／だ` 组成 16 格，再排除该类别的正确尾。生成器逐一尝试完整前部后的错误尾；词汇编辑则逐位置生成一次同类假名替换、遗漏、重复插入或相邻异字颠倒，搭配固定错误尾「だ」，避免把所有词汇编辑与所有错误尾相乘。它只覆盖这组有界操作，不宣称枚举所有混合错误。

允许改动的是**原题词汇中不变的前部**；原动词转段以及「たが」等派生接续必须完整保留。遗漏后至少保留一个字符，插入须与相邻原假名同类，颠倒只限相邻、不同且同类的假名。两个以上位置的独立词汇损坏、非法字符、派生接续损坏和范围外目标均不能获得本规则的补查。若接受变体可以把同一输入解析成不同的词根／词尾边界，也继续保守，不选择一个方便的解释。

正确答案、合法缩约、已有明确知识点归因、严格类别／促音阶段定位、单纯词汇笔误仍优先。例如「しまたがった」保持词汇重试；「しめたがた」保留严格阶段定位；「しめたがっだ」仍按已有过去接续规则处理。新模式中这些重合输入沿用对应独立约定，不能为了增加补查数量覆盖更明确的结果。

若后续练习已经明确提供词类，再次出现混合差异时只显示局部观察，`review` 的后续步骤必须为 0，禁止递归追加。词汇差异只展示原词的固定前部，如「しめ／しま」，不提前展示完整正确过去形式。审计同时阻断混合原答直接计分、范围外原子写入、遗漏后续练习、把补查当作阶段定位，以及在观察中泄露完整正确尾。
