# 沿变化链诊断词类与构形错误

原题或未告知词类的拆步中，如果答案可以由“误套其他动词类别的构形，再发生一个已知局部错误”得到，先询问该阶段的词类，再给定正确词类检查构形。候选路径只决定问什么，不直接证明用户的错误动机，也不产生独立知识点分数。

例如「いる」的たら形写成「いっだら」：过去形阶段存在“按五段变化，再把た写成だ”的候选路径。流程现在先判断「いる」的类别，再检查「いる」的过去形。不会先把一段动词去る规则作为已知条件给出，也不会仅凭原答案扣除词类分数。

## 共用方式

`diagnostic-plan.mjs` 在原有正确变化链中标明各个原生动词构形阶段，包括该阶段的输入、词类、目标和局部规则。`conjugation-path-diagnosis.mjs` 使用这些边界检查候选，不另列たら、たり或每一种复合形式的识别白名单。

1. 对有实际る词尾的动词，构造可能的其他类别变化。不规则动词也可进入三类选择。
2. 在同一原生阶段应用现有有限的局部错误操作，如接续遗漏、重复、清浊音变化或错误词干。
3. 用正确变化链后续节点的明确接续边界匹配最终输入，同时正向核对。不能通过整串编辑距离或任意截取词尾确定错因。
4. 只有匹配位置唯一时才优先检查该阶段。若有多个阶段或分支竞争，保留原有保守拆步。

过去形、て形、否定、ます形、意向形、使役等原生变化及连用接续共用此机制。它们的错误能够在后续接续完整且能保留差异时传播到复合目标。尚未支持的局部错误、其他位置同时损坏或无法确定边界的答案仍进入原有拆步，不承诺为任意错误字符串指定唯一错因。

## 归因边界

- 正确答案、接受变体、其他完整形式和允许重交的词汇笔误优先处理。
- 两个类别给出相同接受形式时，不据此增加分类题。例如る结尾动词的ば形不能仅凭れば区分五段与一段。
- 已给定词类的步骤不重复询问类别。构形仍错误时进入有限的基本操作，基本操作不会递归。
- 既有单一、明确的归因保留；只有额外存在局部错误或竞争解释时，才把原有类别候选转为追问。
- 原词的单一错误可以沿纯追加的接续传播，例如「いだ」的过去接续错误传到「いだら」。仍需由原生分析器独立确认该错因。
- 跨词尾替换或由新构成的表达继续变化时，不靠反向还原强行扣分。例如「たいかった」不能解释成先重复たい的い、再正确完成过去变化，从而误扣たい接续。
- 没有单独检查的前后步骤不记对；分类追问无知识点写入，后续构形只记录辅助练习，原题仍计错并保留独立复测。

## 验证

`conjugation-path-cases.mjs` 用独立的语法阶段约定和人工指定的错误构形生成输入，不调用生产诊断候选。它已接入主错误生成器 `error-patterns.mjs`，常规诊断审核会检查这些输入。

测试覆盖了原题和给定形式、两类与不规则动词、假名归一化、后续变化传播、其他合法表达保护、词根损坏保护、已给定词类的终止性以及知识点和复测状态。故意删除分类题、改错后续规则或加入原题扣分的变异结果必须使审核失败。

实际 React 界面用生成数据验证“原题答错 → 分类判断 → 给定类别构形 → 完成拆步”的完整流程，并核对作答日志。
