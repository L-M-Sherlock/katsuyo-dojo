# 三类可避免冗余的优化

## 比较口径

基线为已发布的 `32bda80`：实际 React 页面在独立 JSDOM 存储中从零运行，每个显示重点第一次作答错误，之后全部正确，不使用提示或拆步，错误明确归因到显示重点。调用页面自己的评分、下一题与下一轮逻辑，直到 43 门课程完成且待复测清零。

这是一个受控评分回放，不生成错误日语字符串，不测试归因器能否从真实输入识别每个错误。它与只计算知识点达标的 `simulateLearning` 不同，包含独立复测和间隔题。

## 修改

1. **刷新未显示的过期题目。** 下一题原本有学习价值、现在已经失去价值，或剩余队列已无可推进的题目时，使用最新分数重新规划未显示部分。主重点未变时保留原有 3:1 节奏；已作答题与当前反馈保持稳定。本轮已用的题目、词语继续参与去重。
2. **安全间隔题优先兼做学习。** 先在非任何待复测目标的候选中挑选能够推进已引入知识点的题目；其次考虑同样满足既有课程开放及先修条件的其他可学习题，最后才使用已掌握内容。普通选题和间隔选题共用同一学习价值判定，不能把只差覆盖的父知识点、或变形题携带的源词分类标签当成额外学习价值。
3. **减少对其他待复测目标的提前曝光。** 有安全备选时不触碰其他 pending，避免答对也不计独立证据、还推迟那个目标的复测。专项模式可使用原本允许的已开放基础分类题作为安全退路。没有安全候选时仍保留只保护最老目标的退路，防止候选极少或全部目标都 pending 时死锁。

没有修改达标阈值、知识点数量、覆盖要求、错误计分、历史分数或两个其他整题的复测间隔。也没有引入时间等待或记忆衰减。

## 完整页面回放结果

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 总原题数 | 1405 | 1163 |
| 错误 | 119 | 119 |
| 正确 | 1286 | 1044 |
| 普通题 | 1049 | 851 |
| 间隔题 | 237 | 193 |
| 复测类型题 | 119 | 119 |
| 轮次 | 142 | 125 |
| 没有学习价值的间隔题 | 228 | 0 |
| 明确过期的普通替补题 | 5 | 0 |
| 提前碰到其他 pending 的间隔题 | 1 | 0 |
| 完成课程 | 43 | 43 |
| 达标知识点 | 119 | 119 |
| 完成覆盖项 | 89 | 89 |
| 剩余 pending | 0 | 0 |

总题数减少 **242 题（17.2%）**。这不是把 228 道间隔题直接删除：间隔继续存在，但兼做学习，因而后续需要单独补练的题目也减少了。119 道复测是题目类型数量；实际答对并清除 pending 的次数为基线 112、优化后 113，其余在同一“首次重点错误”策略下继续保留原复测义务。

普通题中没有推进未达标规则的数量为 65 → 45；其中包含明确的平衡复习，不等于这些题都属于 bug。优化后的所有 193 道间隔题在作答时都有学习价值。该回放没有出现必须动用 `pending-fallback` 的情况，退路由候选受限的专门回归测试覆盖。

模拟仍按“首次作为显示重点”触发一次错误，而非“首次获得任何证据”。优化后的间隔题可以提前积累其他知识点的证据，因此有两个重点在首次显示前已达标，模拟仍强制作错一次。前后策略和总错误次数保持一致；报告不是所有真实学习者的固定通关题数。

## 验证与复现

新增的独立回归验证安全间隔、学习价值优先、全 pending 防死锁、专项分类退路、过期队列识别、真实页面中途达标后的换题，以及反馈不被分数变化替换。标准全套测试共 **757 项通过**，知识模型与目录审核、类型检查、ESLint、生产构建通过；全对及原有混合作答模拟也能完成全部知识点与覆盖。

完整页面回放现在是仓库命令：

```sh
npm run simulate:first-error -- --output /tmp/katsuyo-first-error-report.json
```

输出包含逐题学习价值、计划时与作答时状态、间隔目的、pending 碰撞、过期替补及复测解除。若无法完成全部课程、出现过期学习替补或可避免的 pending 碰撞，命令失败。该完整回放按需运行；普通 CI 继续使用算法和 UI 定向回归，不把所有已学内容题一律判成冗余。

以上为发布前的本地验证结果。
