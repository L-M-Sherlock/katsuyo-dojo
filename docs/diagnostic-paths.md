# 诊断路径与自动检查

此前的候选匹配能保护掌握度，却没有保证每个未知错误都有可继续的诊断路径。现在保留已有的精确归因，并为全部 131 种形式建立正确变化路径，普通动词、形容词、派生助动词、缩约和不规则尾部使用同一套基本操作。

## 用户看到的流程

以已给定「閉めたがる」，要求否定过去、填写「しめたがりない」为例：原答同时存在词干差异和仍停在「ない」的问题，不能直接挑一个知识点扣分。系统说明这两处可观察的差异，然后依次给出：

| 已给定的形式 | 本步目标 | 本步可评估规则 |
|---|---|---|
| 閉めたがる（五段动词） | ア段词干：閉めたがら | `stem.godan.a` |
| 閉めたがら | 接否定：閉めたがらない | `suffix.negative` |
| 閉めたがらない（い形容词型） | 过去：閉めたがらなかった | `adj.suffix.i-past` |

页面只在本步作答后揭示本步正确形式。每一步提供正确输入与所需词类，避免让前一步错形继续污染后面的判断。已确认的操作跳过，知识点不重复记录。旧的“类别判断 → 给定类别再活用”探针如果仍无法定位，也会继续拆为基本操作，不会再次询问类别。

能从原答唯一确定的错误仍直接归因。若已写出完整正确中间形式，沿用原有的部分正确证据，只检查剩余变化。差异观察与知识点证据分开：看到某个字符不同，不等于已经证明某条规则不会。

## 计分与终止

- 原题只记一次；拆步不增加今日题数、正确题数、连对或整题作答速度。
- 基本步骤只评估当前规则，不给已经提供的词类、整个表达的应用能力或覆盖切面加分。
- 同一知识点在一次拆步流程中最多写入一次；队列去掉已经评估的规则和已经检查过的节点。
- 提供了正确输入与规则后，若固定前部完整而本步变化有误，可以记录该操作错误。前部也损坏、输入无法辨认或仍有竞争解释时，只说明差异，不猜测扣分。
- 基本步骤不再递归。输入无法辨认时给出明确的结束反馈；可以随时跳过剩余练习。
- 空白、只有可忽略标点或超过 256 个字符的输入要求重填，不消耗题目或拆步。原有的唯一词汇笔误重试继续优先。
- 只有保存成功才推进队列、汇总已更新知识点；保存冲突不会显示已经完成的反馈。

知识点 ID、课程顺序、历史进度和迁移规则不变，也不回溯改写以前的作答。

## 正确路径与独立检查

`app/lib/diagnostic-plan.mjs` 声明正确操作，既不存储错误输入模板，也不靠编辑距离给知识点评分。每条路径记录中间词形、实际词类、目标操作与规则。否定过去按否定再过去展开；「受身 → たい → 否定过去」保留たい；短使役的五段尾部、ある／いく／くる等特殊尾部以及合法缩约保留自己的路径。

`scripts/lib/diagnostic-oracle.mjs` 是单独维护的测试约定，不导入生产诊断路径或候选。完整正确词形由已有活用器提供，操作次序、规则、类别和每个基本操作的输出另行核对。删除中间步骤、交换顺序、写错知识点或将“过去”标签配上否定答案，都会使检查失败。

`scripts/lib/universal-error-cases.mjs` 根据独立操作约定生成输入，覆盖以下范围：

| 范围 | 生成内容 |
|---|---|
| 全词库、全部形式与接受变体 | 正确答案及规范化对照，连续片段遗漏／重复、同一操作内两处不连续字符遗漏、相邻颠倒、清浊音、大小假名、错行、停在中间形式、同词其他形式、词汇差异 |
| 全部基本操作上下文 | 给定输入下的正确／错误操作、合法缩约、损坏固定前部、无效输入；明确检查应更新哪个规则及哪些规则不能更新 |
| 每种结构的代表词条 | 两个不同节点的错误组合、词汇与活用混合、三处以上错误、固定种子模糊输入 |
| 实际拆步状态机 | 全对、全部无法识别、交替对错，以及旧类别探针进入基本操作的流程；检查终止、重复节点、重复计分、显示目标和答案泄露 |

结构按目标形式、词类、五段词尾、行く例外、する／くる、いい和な形容词末尾い分层，不能用少数随机词条代替结构覆盖。固定种子使模糊输入可复现。分类题另行核对正确与错误选择。

精确归因审计现有 54 类错误模式，继续验证精确归因和保护边界。其中「閉める → しめせれる」在整题与使役受身构造的拆步中，都明确要求归因到 `suffix.causativePassive`，不追加词干／接续补查，也不更新词类、词干或整题应用掌握度；元测试删除这项归因时必须失败。两处遗漏限定在同一个接续内部，不把相邻知识点合并后强行归因。

2026-09-09 增加两个独立的阶段优先模式，审计模式总数为 54。原题匹配明确的派生词过去变化冲突时，可以从中间词类与过去变化开始补查；完整前部、其他合法表达、共享规则的范围仍受约束。实现与示例见[阶段优先补查](probe-routing.md)。

原先的零探针合同仍禁止伪造具体错因，但允许新的基本操作补查；补查必须满足独立的输入、目标、范围与终止合同。元测试会故意删除补查、引入错误规则、泄露答案、重复记录或缺少报告分片，确认检查确实能阻断这些回归。

有限生成器不能穷举任意长度的自然输入，也不能从所有错答还原学习者的真实想法。这里保证的是已支持形式都有完整的诊断路径，并用明确规则区分可以归因、需要补查和证据不足的情况。

## 运行与回放

```bash
# 两层全量检查；同 CI 和发布流程
npm run audit:diagnosis:parallel
npm run audit:paths:parallel

# 快速检查全部结构代表
npm run audit:paths -- --representatives --output outputs/diagnostic-representatives

# 限定形式，仍覆盖这些形式的全部词条
npm run audit:paths -- --forms tagaruNegativePast,adjectiveNaNegativePast --output outputs/diagnostic-focus

# 回放保存的最小化反例
npm run audit:paths -- --replay outputs/diagnostic-paths/minimal-counterexamples.jsonl --output outputs/diagnostic-replay
```

报告位于 `outputs/diagnostic-paths/report.md` 与 `summary.json`。失败上下文写入 `failures.jsonl`，缩减后的反例写入 `minimal-counterexamples.jsonl`。回放会从当前实现重新构造基本操作，而不是沿用序列化的旧实现。缩减保留独立预期的适用条件和原失败代码，不能把合法答案缩成所谓反例。

分片按目标形式互斥。缺少、重复、崩溃或范围不符的分片不能合成为“全量通过”；前一份已合并报告保留。用例计数、结构数、实际流程步数和违规总数分别报告，不能用大量相似输入夸大直接归因能力。

### 五段ア段后误接「させられる」

「飛ぶ → とばさせられる」保留了正确ア段词干「とば」，但应接「せられる」。基本形以及过去、否定、否定过去都识别这个有界的接续混用，只更新 `suffix.causativePassive`，不把后续结尾视为独立应用正证，也不重复检查ア段。

识别要求完整词根和正确ア段均保留，后续形式必须能由该错误中间形式按一段动词完整生成。词汇、词干或结尾另有损坏时保留原来的诊断／拆步；要求缩约的题目也不直接归为同一单点错误。各五段词尾、汉字与假名、辅助计分隔离和冻结语料的审查结论均有回归验证。
