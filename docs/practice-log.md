# 作答日志

在「知识进度 → 作答日志」查看最近操作。展开一条记录，可以看到原词、目标形式、提交答案、判定说明，帮助条件、待复测变化，以及独立掌握记录与辅助练习记录的前后快照。

日志从启用后的新作答开始记录。只有累计掌握度的旧备份不能恢复逐次作答历史，导入后从空日志开始积累。

## 记录哪些操作

- 原题提交：正确、错误、查看答案。
- 展开提示：立即记录帮助条件与目标曝光，尚未提交也会持久保留待复测，防止刷新后被算成无帮助作答；收起提示不新增事件。
- 原题与拆步中的笔误重试、无效输入：保留判定，但不增加答题数或知识点统计。
- 拆步提交：记录给定形式、当前目标、步骤编号、作答前后的总步骤数。诊断性词类选择也记录，知识点更新列表为空。
- 完成或跳过拆步：记录当时已作答的步骤数，原题结果保持不变，待复测继续保留。
- 旧数据迁移：保留原事件，另外记录可以核验的历史加分修正。

未触发提交判定的键入、空白提交、单纯切换页面不生成作答记录。同一道原题和它的重试、拆步、结束操作共用 `questionId`；再次抽到同一词条时会使用新的 ID。

## 如何检查最后更新的知识点

导出文件的 `profile.practiceLog.events` 按写入顺序排列，最后一项是最近操作。`sequence` 保留连续写入顺序，即使设备时钟改变也不按时间重新排序。

查看事件的 `changes`（主掌握记录）和 `assistedChanges`（辅助练习）：

- 非空：每项都包含 `kcId`、当时的中文名称 `label`、完整的 `before` 和 `after` 统计快照。首次创建记录时 `before` 为 `null`。
- 空数组：这次操作没有改动对应渠道。拆步的 `changes` 始终为空，局部练习结果写入 `assistedChanges`。可以结合 `outcome` 和 `diagnosis.message` 区分答错未归因、笔误重试、诊断性选择、跳过等情况。

如果最后一条是「完成拆步」，它通常没有知识点更新。沿同一 `questionId` 向前查找 `changes` 或 `assistedChanges` 非空的记录，就能确定最近真正发生的更新。`diagnosis` 是分析结果，两个变化数组才是本次实际写入的变化；已经评估过的规则不重复计分。

| 字段 | 含义 |
|---|---|
| `id`、`sequence`、`at` | 事件标识、写入序号、UTC 时间；界面按设备时区显示时间 |
| `questionId` | 所属原题，关联原题及全部拆步 |
| `type`、`outcome` | 操作阶段与判定结果 |
| `exercise` | 原题词条、读音、词类、课程与目标形式 |
| `target` | 本次给定输入、目标、接受答案、可评估知识点、步骤编号和总步骤数 |
| `answer`、`answerLength`、`answerTruncated` | 原始提交文本及长度；超过 256 个字符时只保留前 256 个并标明截断 |
| `hintUsed` | 本题是否使用过提示，收起提示仍保留该记录 |
| `diagnosis` | 分析器指出的错误、已确认规则与说明 |
| `support` | 是否独立、帮助来源与已提供的中间式/词类/规则；旧事件可无此字段 |
| `changes` | 主掌握记录的前后完整快照；迁移事件记录历史修正 |
| `assistedChanges` | 局部辅助练习的前后快照，不影响独立掌握度 |
| `assessment` | 所属目标的独立/辅助次数、待复测前后状态与本次复测资格 |
| `totals.before`、`totals.after` | 日期、今日答题数、答对数和连对数，供检查拆步是否错误影响原题统计 |

例如「増える → たがる・否定形」中，第一步答对「ふえたがる」会在辅助渠道记录已评估规则；第二步输入「ふせたがれない」时，`changes` 为空，步骤总数由 2 变为 4；后续分别在辅助渠道记录ア段词干和否定接续的实际结果，待复测不因此解除。不会把第二步的多处差异强行记成某个知识点错误。

界面不从日志展示尚待补查的正确答案；完整的接受答案保留在导出数据中，供离线检查。日志只保存在当前浏览器，不上传。

## 保留、导出和恢复

日志使用独立的内部版本 `practiceLog.version: 2`（同时可读取版本 1 的历史日志）。最多保留最近 500 条，紧凑序列化后的日志长度也限制在 750,000 个字符内，以免复杂题的大量知识点快照占满浏览器存储。容量不足时裁剪最早的完整事件：

- `totalEvents`：累计记录数量。
- `droppedEntries`：已经裁剪的较早事件数量。
- `events`：当前保留的完整事件，序号不重置。

「导出数据」同时备份进度和当前保留的日志。新导出格式版本为 5，Profile 为 7，当前页面继续支持版本 1—4 的旧备份；不支持日志的旧页面会拒绝新格式备份，避免导入时静默丢失日志。新版评估状态直接恢复，不重放日志。升级旧版备份时，迁移器只回放可核验的连续快照来纠正辅助加分，另记迁移事件；没有证据的历史不猜测。

独立成绩、辅助记录、待复测和日志通过同一次保存提交。重复提交受到已有提交锁保护；跨标签页冲突时两者都不提交。浏览器写入失败时，两者一起保留在本页内存，可通过已有的「导出本页记录」取出。

清除本地进度也会清除日志。恢复旧备份会使用备份所包含的历史，无法补回已经裁剪、未曾导出或尚未启用日志时的操作。

## 自动检查

`tests/practice-log.test.mjs` 检查「増える」完整流程、统计快照、零更新事件、容量裁剪、导入导出、格式校验和原子保存。`tests/page-interactions.test.mjs` 通过实际页面检查重复提交、展开拆步、跳过、Enter、查看日志、导出与重载，以及写入失败时的内存备份。
