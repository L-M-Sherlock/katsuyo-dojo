# 活用道场场景用法卡

交付能够直接进入当前卡片接口的内容。日语整句自然、目标与词义匹配、前后文与译文一致，比填满数量更重要。结构校验通过只说明接口可用，不等于语言审核通过。

## 按角色使用

本仓库的维护版本位于 `.agents/skills/write-katsuyo-usage-cards/`。在本项目工作时从此目录读取规则和脚本，不依赖个人技能目录的同名旧副本。

- **协调者／主代理**：负责课程或大批扩充任务时，先读[协调与接入流程](references/coordinator.md)。从实际题池生成缺口、划分不重叠批次、调度作者和审核者、维护队列与快照，并按单份独立审核报告汇总结果，再接入和验证。主代理只做协调、机械门禁和状态裁定，不代替审核者逐卡作语言判断；审核结论存疑时保留待核实或返修，不能凭自己的直觉批准。
- **作者**：按本文件及分配清单编写，只交付所负责的 `draft` 和报告；不改清单、总目录或教学规则来过检查。
- **审核者**：独立读取不可变作者快照，逐卡判断完整句、角色、译文和 reading，写带卡片哈希的报告。每个新阶段只分派一名 `gpt-6-sol`、`medium` 审核者；其独立报告替代主代理逐卡语言裁定。

先辨明角色，再加载相关材料；内容子代理无需承担整个项目的课程模拟或发布。任务同时包含编写与审核时可以承担两者，但交付中如实说明自审、独立审核和主代理复核分别由谁完成。

## 确定本批任务

- 以任务给定的仓库、词条／形式清单和可修改文件为边界。先读仓库的 `docs/usage-cards.md` 与 `app/lib/usage-cards.mjs`，核对当前接口；本 skill 的字段示例和长度约定不覆盖仓库的新规定。
- 区分新增词形组合、修改旧卡与独立审核。查看既有 ID 和词义／形式组合；扩充时不要覆盖原代表卡，也不要沿用已经占用的 `usage:form` ID。
- 不把某次批次的卡片数或代理数写成长期要求；从当前课程和任务清单获得范围。角色是内容编写子代理时，只改获分配的数据文件，不顺手修改框架、词库、筛选、判分或测试以让内容通过，也不自行再次委派。
- 编写可能、受身、使役或使役受身时，额外读[可能与态审核](references/voice-review.md)。清单的 `transitivity` 和 `usage` 用于核对角色与适用条件，不是现成例句，也不保证任意搭配自然。
- 编写连接与条件阶段时，额外读[连接与条件审核](references/linking-review.md)，先确认前后项关系及本课采用的用义。
- 编写意愿与要求阶段时，额外读[意愿与要求审核](references/intentions-review.md)，核对愿望主体、第三人称外在表现、非意志变化、许可／邀请和义务表达的否定方向。
- 编写或审核动作与状态阶段时，额外读[动作与状态审核](references/actions-review.md)，核对体貌、准备结果、授受角色、否定范围、方向视点与语体。
- 编写或审核综合运用阶段时，额外读[综合运用审核](references/integration-review.md)，按整条组合确认愿望、许可、授受和否定作用域。
- 未指定分片文件时，主代理按课程或表达族划分互不重叠的输出文件。仅在任务已授权委派时使用子代理。
- 按当前项目配置，**作者子代理使用 `gpt-6-luna`、`max`，审核者使用 `gpt-6-sol`、`medium`**。分派时显式设置模型与推理强度；不可用时记录失败，不悄悄换配置。主代理不承担逐卡语言裁定，也不能把自己的自审伪装成独立报告。作者自审不能替代审核者报告；同一代理不得同时作为该阶段作者和审核者。可用资源充足时，工作池可暂以 6 名作者和 8 名审核者为配置示例；这是扩容起点，不是长期固定并发数。

综合运用批量交付按[三级流水线](references/staged-workflow.md)执行；旧任务保留[协议 2](references/coordinator.md#协议-2先提交再验收)历史。负责人提交完整快照并停止写入，一名审核者按不可变快照独立报告；主代理只核验报告、处理状态和接入门禁。通过检查、完成提交和审核通过是三个不同状态；返修产生新版本，不覆盖已交付快照。

## 编写

1. 用当前词义审核与活用器获取合格候选和实际答案。可使用下述 `prepare` 工具，或读取任务附带的清单；不靠回忆拼 `form`、`senseId`、释义或复杂答案。
2. 先拟好“场景＋完整日语句＋译文”，逐句检查，再拆出 `before`／`after`。完整目标形由项目活用器插入唯一槽位；不要把愿望、否定、过去等目标的一部分放在槽外，也不要自行保存另一套答案。
3. 正面只给简短中文场景与挖空句。当前约定是场景以 12～24 字为目标、最多 32 字；不是要求为凑字数加话。场景说明具体人物、对象或处境，不写“谈论某事与某人的关系”，不用“什么时候用”长标题。
4. 场景可以补充句外背景，译文只翻译日语实际表达的内容。先从生成的完整目标反向核对含义，尤其原词本身的意思和否定作用域；场景、例句与课程说明须一致。课程说明和参考教材不是永久的用义上限：发现自然且适合教学的其他用法时，交协调者核实并同步扩展说明，不能仅因旧概括未提及而拒收，也不能让卡片悄悄换义。核对愿望／能力／动作发生、完成／经历、肯否、时态、授受视角与语体；不能机械改后缀后沿用原译文。
5. 正文 `text` 使用自然的日语书写：常用词用常用汉字，并在 `reading` 提供对应假名；不要为了省注音而把整句改成全假名。助词、助动词和习惯用假名的词保留假名，不强行汉字化。正文与读音的标点、片假名和分段保持对应，先看实际生成的注音。详见[正文与注音](references/editorial-review.md#正文与注音)。可选 `note` 最多 60 字，译文最多 160 字；不用长说明挽救生硬例句。
6. 新写的子代理稿件标记 `draft`。使用 [语言审核要点](references/editorial-review.md) 检查完整句；拿不准时核实可靠日语教学或语言研究来源，或换一个合适场景。任务允许选择代表词时才可换词；若清单固定了词义／形式，不得以另一个词代替未完成项。不为凑齐数量编造自然度或自行放宽词池。

注音要分开核对“词义对应的读法”与“页面上的分界”。先按完整句独立读一遍，再对照作者填写的 `reading`；同一个汉字有读音不等于该读音适合当前词义。正文改写时同步重审读音，避免保留旧句读音。批量稿件使用下述独立词典对照，逐项判断差异，不能只检查字段非空。

综合运用使用[三级流水线](references/staged-workflow.md)：3 张 pilot 经一名审核者批准后，作者编写 10–15 张独立扩写稿；再次通过后，仅补写剩余配对，每块最多 5 张。作者始终只写派发的隔离目录，正式 `NN.cards.json` 由主代理合并经单份独立报告批准的不可变快照。每阶段开始前核对清单解析、精确范围和实际作者句柄；作者使用 `gpt-6-luna max`，审核者使用 `gpt-6-sol medium`。协调器按作者和审核队列背压扩容，不一次启动整批作者；作者或审核者完成后由状态事件连续补位，不能用留言假装代理正在运行。两次实质失败退回微型试稿；以工作池实际可观察的批准、返修和队列状态衡量进度，不把未实现的指标命令写成已存在。规则、失败样例表、命令和审核字段见该引用。

逐词扩充时先为一个词的全部分配形式写出明确的「场景、前句段、后句段、译文」记录，再进入下一个词。小批试稿合格不保证大量扩写合格；若一次扩写开始出现通用后项、词义拼接或占位翻译，停止整批生成，缩小下一次编写范围并逐句返修。未终审的稿件应保持 draft 交给审核者，不以“还未审核”作为不编写草稿的理由。代码可复用元数据和组装函数，不能用「过去则统一加昨天」「否定则在中文动词前加没有做」或通用后项批量生成教材。每种形式都应有可直接审阅的具体内容；没有用到的示例字段或被生成器覆盖的后句段应删除，避免作者审的句子与实际展示不同。

`context` 是内部适用性说明，不是学习者场景。允许入库只是选词的必要条件；不能直接复制 `context.text` 或把它当成完整用法的证明。分类题不配变形卡；没有精确匹配的题目不借用别词的卡片。

固定词义／目标形式的原稿被退回后，若三个内容不同的返修稿仍分别因自然度或用义问题被审核者拒收，暂缓该精确配对的常规出题；原稿不计入这三次返修。审核者若在报告中明确判断该固定词义、目标形式及课程用义下没有自然表达，并写明具体依据，则直接暂缓，无须等待三次返修。同一稿重复检查、结构或注音校验失败、三张审核票都不算三次语言返修。保留审核报告、稿件指纹、构形识别和恢复条件；详见[协调者流程](references/coordinator.md#4-处理语法与出题适用性的边界)。

## 工具与交付

`SKILL_DIR` 指正在使用的本技能目录；仓库内可设为 `"$PWD/.agents/skills/write-katsuyo-usage-cards"`。以下命令在目标仓库根目录运行，换目录执行时显式传入 `--project`。工具只读取项目和卡片，只有显式 `--output` 才写任务清单或报告。

```bash
node "$SKILL_DIR/scripts/card-workbench.mjs" prepare --project "$PWD" \
  --forms passiveDesireNegativePast,temorauDesireNegativePast \
  --output /tmp/usage-card-assignment.json

node "$SKILL_DIR/scripts/card-workbench.mjs" check --project "$PWD" \
  --input /tmp/usage-card-draft.mjs \
  --forms passiveDesireNegativePast,temorauDesireNegativePast \
  --output /tmp/usage-card-review.md

# 在临时 Python 环境里对照 UniDic；只生成复核候选，不修改卡片。
uv run --no-project --with 'fugashi[unidic-lite]' python "$SKILL_DIR/scripts/reading-audit.py" \
  --project "$PWD" --input /tmp/usage-card-draft.mjs \
  --output /tmp/usage-card-readings.json
```

- 逐词补齐课程时，用 `prepare --stage basics --missing-pairs` 等生成固定词义／形式清单；`--stage` 对应网站课程分组，`--group` 是内容制作分工（其中 basics 还包含态），不要混用。`check --assignment` 自动按清单的精确词义／形式验证，不能用同一词类的另一个词凑数。大清单按词条分片，相关肯否／时态可以复用合理人物背景，但每个完整句和译文须分别审核。清单是逐对要求，并非每个词乘全部形式：某个词可能已有部分代表卡，不得自行补全笛卡尔积。调用方给定的清单只读，不能从自己生成的稿件重新造一份清单来宣称覆盖通过。
- 补齐词类时，用 `prepare --missing-classes` 生成当前尚缺的“形式 × 词类”清单（可按 `--group` 分片）；每行是一条独立要求，候选截断按词类分别进行，避免不规则候选被五段词挤掉。用 `check --assignment 清单.json` 验证每个分配组合恰好一张，而不只是形式数相同。
- `prepare` 接受 `--forms` 或当前项目 `USAGE_CARD_GROUPS` 的 `--group`，列出所有合格候选、实际答案、含义与已占用卡片。清单较大时按目标形式读取，避免把整个文件灌进一次工具输出。
- `check` 可检查尚未接入总目录的 `.mjs` 默认导出数组或 `.json` 数组；按词条归组输出完整句、读音、挖空句及结构问题。连看同一词的全部形式，检查时间、肯否、后项和译文是否随实际句子正确变化。指定 `--forms` 时核对缺失与越界形式；同时报告现有卡片冲突，修改旧卡的同 ID 不自动判为冲突。
- 批次交接前运行 `review-preflight.mjs --task-root <任务目录> --batch lane/NN --phase author|review`。它检查范围、结构、字段与 ledger，并提示语言复核重点；重复／模板理由规则只是启发式检查，不证明理由真实，也不判断日语自然度。提交命令会重新校验，不能沿用旧输出。
- 综合运用新写入使用协议 3；协议 2 仅供旧任务维护。作者以 `gpt-6-luna max` 编写，一名 `gpt-6-sol medium` 审核者独立审核；主代理只协调并核验该报告。协议 2 的 `main` 审核记录仅为历史兼容，不作为新批次的独立审核替代。
- 整合前由已分派的一名审核者逐条复核，协调器仅在有效报告逐卡批准后把阶段改为 `approved`。报告缺失、拒收或待核实时保持待审／返修；不要求用户逐卡确认，也不自动把结构合格稿批准。
- 如果校验报告含 `writingReview`，逐条检查提示的全假名长句或连续平假名。它只是人工审核候选，不是“每句必须有汉字”的规则；自然的假名与片假名词可以保留，也不能靠换一两个汉字消除提示后就跳过其余正文审核。
- `reading-audit.py` 省略 `--input` 时核对整个项目目录。输出包括全文、译文、词义 ID、目标形式、原读音与词典差异；需本机 Node 和临时安装的 fugashi / unidic-lite，不加入应用依赖。词典可能误判多音字、连浊、数字或派生目标，候选不能直接算错；零差异也不能证明语境正确。按[注音复核](references/editorial-review.md#注音复核)处理，报告区分确定错误、合法异读和分词工具的误判。
- 接入后使用项目的 `npm run audit:usage` 和相关内容测试。若扩充例词遇到固定总数或“每形式／词类一张”的断言，把需要调整的验收口径交给主代理；内容子代理不得降低断言或删旧卡消除失败。
- 审核报告以最终文件为准；改稿后须重跑受影响的完整句、读音及结构检查，不能沿用改稿前的候选统计或未实际输出的句子。
- 审核任务必须携带不可变 packet 的完整绝对路径、作者 receipt 和 count；审核者不搜索目录、按 mtime／revision 猜稿，也不在没有新 packet 时重审旧稿。`readings.candidates` 以精确 `id` 列出；`retain|error` 只表示作者 reading 是否保留或修正。
- 生成失败时先修复生成，再重新检查和提交；不能让后面的命令继续冻结旧文件。PowerShell 的分号不会因原生命令失败而停止后续命令，不能用 `生成; 检查; 冻结` 作为交付步骤。只读搜索未命中不是交付失败，可定位正确路径后继续。
- 交付说明写清实际卡片数、覆盖的形式数和词义／形式对数、修改路径、校验结果、审核状态与未解决问题。代表卡覆盖一种形式，不代表覆盖该形式的所有词条。
- 卡片是静态教材，不读取个人进度备份来编写内容或测试；不因内容任务自动提交、推送或发布项目。
