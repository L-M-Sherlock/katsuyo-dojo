# 综合运用：整条组合的用义

制作与接入按[三级流水线](staged-workflow.md)执行。这里仅列整条组合的语言判断；不把合法句架或中文词列成禁用表。

用于 `stageId: integration`。以 `multi-step-forms.mjs` 的整条表达、实际答案和固定配对为准；内层动词可活用，不保证套上外层后仍适合该词义。结合 voice、intentions、actions、linking 专项中涉及的规则。

- **尝试＋愿望**：愿望主体做尝试；过去否定是当时不想试，不是试过失败。不能把 `てみたかった` 当作实际试做。
- **受身＋状态／遗憾／愿望**：先确定受事和施事，区分正在被做、完成后状态、不愿遭遇以及不想被做。同形的可能／尊敬不替受身背书；否定没有凭空承诺未来也不会发生。
- **使役＋てもらう**：通常是说话人获准或获机会，自己实施原动作。`させてもらえる` 是能获准，`させてもらえなかった` 是过去没能获准；不译成让别人替自己做。许可请求面向有权许可的人，移动词保留来去基点。
- **てもらう＋愿望／可能／请求**：实施动作的是帮助者，获益者为说话人。`貸してもらう` 是对方借出给我，不能照搬原词「借出」翻译成我借给对方。`教えてもらえる` 只说明可以得到教导，不保证学会。
- **可能＋礼貌／条件**：礼貌不改变能力范围；过去可能与结果按句子判断，未完成不自动译成不愿意。能力条件的前后项必须有实际因果或安排。
- **ておく＋请求／条件**：给出具体后续用途；`ておいたら` 区分假设与事后发现。不要只加「先」便把所有动作当准备。
- **たい＋条件**：愿望作为条件，不把条件句译成无条件请求。**すぎる＋否定请求**是控制程度，允许适量发生，不等于完全禁止。

同词的各个肯否／时态／请求形式须分别写明场景、完整句及译文。语境可以复用，不能用程序统一加「昨天」、统一否定中文或用通用后项批量换词。槽外不得补原动词以转成另一复合词，例如将固定「入る」写成「手に入らせてもらう」。

场景可以提供日语句外的必要背景（例如前因、地点或人物关系），不要求逐字复述译文；译文只翻译日语实际说出的内容。审核时分别判断场景是否帮助理解、日语是否表达目标用义，以及译文是否遗漏或增添句中事件，不能因为场景与译文不相同就机械拒收。

发现难写配对时先尝试不同合理场景；保留具体失败稿与问题，交主代理复审适用性。原有明确暂缓的其他课程配对不自动扩大到此处整条组合。

## 本轮暴露的角色和作用域错误

- `待たれる` 表示别人等待我或我的到来；不能译成别人“拖着我久等”，后者涉及使役 `待たせる`。`待てた` 表示能够等待，不保证所等的人已经到达。
- `見せられる` 的受身读法是被展示某物；不能翻成别人看我的伤口。`守られる` 是受到保护或规则被遵守，不能靠中文“战术被看穿”救句。
- 请求 `～ておいてください` 的听话人通常就是执行者；前接 `同僚に` 不会把同事自动变成受请求的第三方。核对 `に` 是询问对象、接受对象还是其他角色，不能只根据助词猜方向。
- `～させてもらう` 中许可方由语境确定；`新人に使い方を教えさせてもらう` 的 `新人に` 是教导对象，不能一律标为许可方。
- 译文不能把动作自动升级为结果：`行けた` 不增加“参加活动”，`泳げた` 不增加“游到对岸”，`書かれている` 不增加未明说的工作人员或强行限定为正在书写。
- `ておいたら` 必须有预备或保留结果的用义。已经先做准备再发现结果可以成立；普通顺序中强加 `おく` 或在槽外接第二个 `たら` 都需重审。

审核者逐卡说明实际证据；冲突由审核者按新快照复审，协调器只汇总结果，不作语言裁定。程序只能组装已填写的判断、句子与指纹；不得按 form 生成通用通过理由，也不得把“完整句”换成“实际句”来绕过预检。词典候选是读音线索，`retain|error` 只判断作者 reading 是否保留或修正，不能把它当作拒绝词典建议；只处理审核 packet 中 `readings.candidates` 的精确 id。每张卡的句法、译文和读音结论分别记录。
