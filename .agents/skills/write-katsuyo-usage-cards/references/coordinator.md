# 协调者：从课程缺口到可接入卡片

协调者对最终范围、语言质量与接入结果负责。作者交回 `draft`，审核者提供逐句判断和返修，协调者在最后核对后批准；人数和模型随任务与可用资源决定。用户指定了作者或审核模型时遵从该选择，不把某次代理数量、模型或卡片总数固定为长期要求。

## 1. 确定范围并保存基线

先读项目的 `docs/usage-cards.md`、`app/lib/usage-cards.mjs`、`app/lib/unified-curriculum.mjs` 和 `app/lib/form-eligibility.mjs`。用仓库当前的词义、活用器和许可推导要求，排除分类题；核对课程采用的具体用义，不能因为同一个词尾还有其他合法用法就扩大课程。

分清用户要求的是逐词完整覆盖、补形式／词类代表卡，还是修订已有内容。`--stage` 是课程阶段，`--group` 是制作分组，两者不能互换；范围未明时先按实际课程边界盘点，并继续不依赖澄清的工作。

在任务临时目录记录：当前提交、工作区已有改动、词义审核版本、目标阶段／形式、全部原卡内容、范围内要求与已覆盖配对。已有卡片的 ID、词义、形式和文本都属于基线；只核对数量或 ID 不能证明旧内容未变。个人学习备份不用于制作卡片或测试。

从仓库根目录生成缺口的例子（替换阶段 ID 为本次范围）：

```bash
SKILL_DIR="$PWD/.agents/skills/write-katsuyo-usage-cards"
CARD_WORK_DIR=$(mktemp -d "${TMPDIR:-/tmp}/katsuyo-cards.XXXXXX")
node "$SKILL_DIR/scripts/card-workbench.mjs" prepare --project "$PWD" \
  --stage intentions --missing-pairs --output "$CARD_WORK_DIR/requirements.json"
```

`requirements.json` 是由当前项目推导的原始要求。给它保存校验和或只读快照，允许每轮只准备或分派一部分，把尚未分片的要求单独保存为未分派集合，不要求一次启动全部作者。检查每个分片内部无重复、分片之间及与未分派集合均不重叠，并验证“已分片要求＋未分派集合＝本次完整缺口”。不要用作者产物反向生成“正确清单”。同一词可能已有部分形式的卡，缺口不是“词数 × 全部形式”；不得自行补齐并覆盖已有代表卡。

若缺口为零，说明该范围已覆盖；不要为履行“补齐”而重复创建卡片。若审核或其他代码修改改变了基线，保留旧要求与决策记录，通知受影响代理停止按旧清单写入，再由协调者重新生成要求并交接，不能静默改掉原清单。

## 2. 分派小批，明确交接

| 角色 | 可负责的内容 | 不应代替的职责 |
| --- | --- | --- |
| 作者 | 指定内容文件、临时校验与自审报告 | 修改输入清单、题库、框架、测试或全局索引 |
| 审核者 | 指定稿件的实际整句、读音、译文及获授权返修 | 改变固定词义／形式来避开问题，擅自放宽许可 |
| 协调者 | 原始要求、分片与文件归属、未决裁定、批准、接入及验证 | 以结构通过或摘要“已完成”代替语言审核 |

把共享 skill 路径、相关专项引用、不可改的清单、唯一输出文件和报告位置写进每个任务。资料与输出用明确路径，不能假设子代理知道主代理的临时变量或工作目录。不必把整个历史对话和所有课程数据复制给每个作者。

先从每类表达挑选一个小批，覆盖普通词、不规则词及明显的词义边界。协调者读实际成句并反馈后，再安排下一批。批量大小按已观察到的质量调整：扩写一旦出现通用后项、占位翻译、全假名省事稿或报告与产物不符，就暂停该作者扩写、缩小任务、整批返修；不要只重复“请认真”后继续派更大的清单。

不同分片可以并行推进；已通过试稿的作者交出一批后，可以处理另一个独占分片，无需等全部内容写完才开始审核。同一时刻一个数据文件只有一个写入负责人。作者结束并明确停止写入后，才交审核者；审核者结束后，才由协调者规范化数据或接入。空闲代理可以接下一项互不冲突的小任务；达到代理数量限制时复用可用代理或继续本地工作，不不断创建新代理或让代理互相等待同一文件。

作者任务可按下列信息组织，不要求照抄措辞：

> 读取仓库内 skill 与所需专项规则。按指定只读清单逐条制作，仅写指定内容文件及临时报告；固定词义／形式，每卡显式保存实际场景、句段和译文，状态为 draft。用当前活用器还原整句，执行精确清单检查和读音对照，列出具体未决项。完成本批后停止写入，不自行扩写其他文件或再次委派。

审核任务另明确：是否允许直接返修、需保留的原稿、逐卡报告内容和停止写入的交接点。未经授权不能让两个审核者同时改同一文件。

## 3. 检查产物，再决定返修或批准

先跑分片的 `check --assignment`，协调者同时核对最初保存的要求没有变化；不要接受作者改用 `--forms` 后声称精确覆盖通过。形式数相等不能证明每个词义／形式都完成。新增任务还应与旧卡 ID 检查交集；工具对同 ID 的稿件可能只报告 `replaced`，不等于授权覆盖旧卡，只有明确的修订任务才按约定替换。合并时再做一次总范围的精确检查，防止分片间重复、漏项或误覆盖旧卡。

语言审核必须覆盖本批每张实际生成句：`before + resolveUsageCard(card).target + after`，连同场景、译文和读音一起读。作者自审之后，大批内容应安排另一审核者独立读稿；协调者亲自复核争议、返修、模板高风险批次和接入版本，不把“随机抽查无误”写成“所有句子已逐句审过”。若只有一个代理可用，可逐批自审并如实注明，不能虚构独立审核。

依据[完整句审核](editorial-review.md)和表达族专项规则，分开处理：

- **结构或范围错误**：缺卡、越界、重复、错词义、目标槽外泄露答案等，修复后重新检查，不降低校验要求。
- **明确语言错误**：不通顺、前后无真实关系、时态／否定错误、原词义漂移、译文遗漏或添加事件、注音错误，按固定配对返修。
- **措辞建议**：可以改善但不代表原句错误，报告与实质错误区分。
- **未决配对**：记录卡片 ID、当前完整句、疑点、尝试和证据，不标为 approved，也不藏进“已完成”数量。

逐项判读 `reading-audit.py` 的候选。词典可能把合法异读、数字音变或派生词分错；不能自动替换，也不能把候选数当错误数。改写日语后同步译文、读音和必要的 ruby 分段，再复读实际结果。抽查页面的挖空与答后显示，用真实组件确认注音分界，不用另一套预览渲染规则代替。

报告对应最终文件：至少记录实际配对数、审核状态、未决项和校验结果；大批或多轮返修保留原稿、实质前后差异及最终文件指纹。对仅有格式／注音拆段的变化另行计数，不把“改过多少卡”当模型错误率。作者修改了最后一句，旧的全量报告也不能继续被称为该文件的最终审核。

多轮交接时，给每张卡保存 `id`、实际审阅的完整句、状态、具体理由和内容指纹。指纹统一取源卡对象 `JSON.stringify(card)` 的 SHA-256，不混入文件名、报告行或辅助字段；接入前重算并拒收未匹配的记录。旧通过结论只有在卡片内容未变且原语言审核确实覆盖它时才能沿用。不能只刷新报告里的句子与指纹却保留旧错误理由，也不能把“没有列在错误表”自动展开为全批语言通过。

协调者须核对报告与实稿：若标为通过的批次仍有占位场景、释义拼接译文、全形共用而肯否冲突的句段，撤销受影响批次的通过结论并实质复审。同一个文件的复审只交给一个负责人；已结束代理的新工作须用能启动新一轮的任务分派，单纯留言不是正在执行。等待前核实代理确实运行，空闲时推进清单核对、返修或接入准备。

## 4. 处理语法与出题适用性的边界

优先核实可靠日语教材、词典或语言研究中的具体义项和完整上下文。同形的可能／尊敬／受身，普通并行／逆接／渐变，动作过程／完成后状态，不能互相背书。实用例可以证明某读法存在，不能单凭一例就声称频率高；搜索不到也不能证明语法不存在。

把结论分成“当前句可修好”“本课采用别的清楚用例”“当前固定配对暂缺合适用例”。有自然读法时不要因初稿差或笼统词类标签整词删除。只有适用性审核需要时，才在用户已有授权范围内调整课程出题限制；不因数量目标扩大课程、改词义或弱化语言标准。

内容制作本身不等于授权重做教学路线。若确实需要超出已有任务范围的改变，先准备具体证据、拟改配对和影响分析，再就缺少授权的部分澄清；已授权的例句返修、代码验证和其他分片继续推进。本 skill 不额外设置逐卡用户确认或发布审批要求。

调整许可时由协调者统一处理，避免作者拿到的活用结果在审核途中失效：

- 保留原形态构造及完整词形识别支持，除非发现另有构形错误；“暂不作为常规题”不等于“日语不能这样说”。
- 按具体词义／形式记录理由、审核版本与前后配对差异；先保存暂缓草稿，再从可接入集合中移出。
- 重新从项目推导要求并发出更新后的分片清单，保留旧清单及变化原因，不以最终稿反推需要多少卡。
- 核对课程说明、题目的表达作用与卡片采用的用义一致，不让界面讲条件而卡片只练反复。

## 5. 接入与验证

对应批次的写入负责人交接后，协调者再次核对实际数据与审核报告，再将通过的卡标为 `approved`，接入内容目录与 `USAGE_CARDS`。没有核准的配对不能因“先上线再说”混入；也不要把尚未整合的文件计为网站可见内容。

对照原卡快照，确认未获授权修改的旧内容逐对象保持不变。分批接入时保留已有覆盖基线，并准确登记本次批准的新增集合；整个阶段补齐前不宣称逐词完整覆盖。新增完整覆盖的阶段应加入项目审计和相关测试，要求来自当前课程、词库与适用性；固定总数仅用于报告，不代替集合相等验证。保留旧测试基线，显式列出审核批准的变更，不重新生成一份“恰好通过”的历史快照。

按改动运行必要检查，避免扩大成无关耗时审计：

| 改动 | 验证重点 |
| --- | --- |
| 卡片或接入 | 分片与合并的精确清单检查、`npm run audit:usage`、相关内容测试；实际显示与注音抽查；受影响的类型检查、lint、构建 |
| 适用性、课程或选题 | 再跑 `npm run audit:eligibility`、`npm run simulate:perfect`、`npm run simulate:mixed` 及相关回归 |
| 诊断或计分 | 验证实际受影响的整题／拆步归因、独立与辅助计分及完整词形识别；按项目要求选择扩展审计 |
| 仅 skill 或说明 | skill 校验、引用与路径检查；脚本迁移或变动时运行真实命令验证，不为文档改动重跑全部学习模拟 |

课程验收不仅检查总题数：检查每个课程形式、首次教学的知识点和覆盖切面仍有题。适用性审计的原始注册池可能是不带语义筛选的基线，要把本轮真实变更前后题池另行比较。

对退出题池的旧复测目标验证两种情况：仍有同路径词时继续保留待复测；已无同路径题时暂停该义务、保留历史，不凭空增加独立答对或掌握度，也不能反复出无关题补空缺。查看审计的 `retestPaths` 逐项目数据，不只看汇总桶数。全对与混合路线都要检查完成状态，重复风险指标与真实残余复习如实报告，不能把某指标为零说成永不重复。

## 6. 收口与迭代

交付说明给出：本次有效要求、原有覆盖、新增与暂缓数量、剩余缺口、实际接入总数、检查结果和未解决事项。分清“已写草稿”“已审核”“已接入”“已发布”，不混用这些状态。

把反复出现、会改变下次决策的问题写进本仓库 skill；一般规则留在入口，专项语法放在引用文件。不要把每个失败例句堆成禁词表。较大的流程改动可以安排独立小批试作：只给真实任务、skill和必要原材料，不提前泄露预期答案；输出放临时目录，协调者检查实际产物后再迭代。试作不会自动进入题库。

批次清单、原稿、字典差异和试作默认留在任务临时目录；仓库保存可维护的内容、工具、规则和必要的汇总复核文档。个人进度备份、机器缓存和一次性完整工具日志不随 skill 入库。

完成内容制作不自动提交、推送或部署。有用户相应授权时，继续按仓库 `docs/publishing.md` 执行既有流程并核对结果，不另换托管平台或重复请求已有许可。skill源码可以随Git仓库版本管理；它不属于网站运行时资源。
