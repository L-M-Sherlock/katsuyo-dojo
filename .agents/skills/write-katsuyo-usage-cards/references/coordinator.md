# 协调者：从课程缺口到可接入卡片

协调者即主代理，对最终范围、语言质量与接入结果负责。作者以 `gpt-6-astra low` 交回 `draft`，主代理亲自逐卡审核、返修并批准。按用户最新要求，不额外创建或复用审核子代理；作者数量按任务与可用资源决定。后续用户另有指定时遵从最新指令。

## 1. 确定范围并保存基线

先读项目的 `docs/usage-cards.md`、`app/lib/usage-cards.mjs`、`app/lib/unified-curriculum.mjs` 和 `app/lib/form-eligibility.mjs`。用仓库当前的词义、活用器和许可推导要求，排除分类题；当前课程用义是盘点基线，不是扩展上限。Yokubi 等来源未讲到某种用法，或旧中文概括只列一种含义，都不能单独成为拒收理由。核实适合教学的自然用法后，由协调者同步更新课程说明与审核规则，再接入相应卡片。

分清用户要求的是逐词完整覆盖、补形式／词类代表卡，还是修订已有内容。`--stage` 是课程阶段，`--group` 是制作分组，两者不能互换；范围未明时先按实际课程边界盘点，并继续不依赖澄清的工作。

在任务临时目录记录：当前提交、工作区已有改动、词义审核版本、目标阶段／形式、全部原卡内容、范围内要求与已覆盖配对。已有卡片的 ID、词义、形式和文本都属于基线；只核对数量或 ID 不能证明旧内容未变。个人学习备份不用于制作卡片或测试。

从仓库根目录生成缺口的例子（替换阶段 ID 为本次范围）：

```bash
SKILL_DIR="$PWD/.agents/skills/write-katsuyo-usage-cards"
CARD_WORK_DIR=$(mktemp -d "${TMPDIR:-/tmp}/katsuyo-cards.XXXXXX")
node "$SKILL_DIR/scripts/card-workbench.mjs" prepare --project "$PWD" \
  --stage intentions --missing-pairs --output "$CARD_WORK_DIR/requirements.json"
```

`requirements.json` 是由当前项目推导的原始要求。给它保存校验和或只读快照，允许每轮只准备或分派一部分，把尚未分片的要求单独保存为未分派集合，不要求一次启动全部作者。检查每个分片内部无重复、分片之间及与未分派集合均不重叠，并验证“已分片要求＋未分派集合＝本次完整缺口”。不要用作者产物反向生成“正确清单”。同一词可能已有部分形式的卡，缺口不是“词数 × 全部形式”；不得自行补齐并覆盖已有代表卡。

若缺口为零，说明该范围已覆盖；不要为履行“补齐”而重复创建卡片。若审核或其他代码修改改变了基线，保留旧要求与决策记录，通知受影响代理停止按旧清单写入，再由协调者重新生成要求并交接，不能静默改掉原清单。

## 2. 分派小批，明确交接

| 角色 | 可负责的内容 | 不应代替的职责 |
| --- | --- | --- |
| 作者 | 指定内容文件、临时校验与自审报告 | 修改输入清单、题库、框架、测试或全局索引 |
| 主代理的审核职责 | 每张稿件的实际整句、读音、译文、返修与语言裁定 | 把审核再分派给子代理，或改变固定词义／形式来避开问题 |
| 主代理的协调职责 | 原始要求、分片与文件归属、批准、接入及验证 | 以结构通过或摘要“已完成”代替语言审核 |

把共享 skill 路径、相关专项引用、不可改的清单、唯一输出文件和报告位置写进每个任务。资料与输出用明确路径，不能假设子代理知道主代理的临时变量或工作目录。不必把整个历史对话和所有课程数据复制给每个作者。

恢复中断任务时，先交叉核对现存产物、审核记录、批次状态和代理运行句柄。新引入的流水线可能尚未登记早期交付；“未分派”不等于“尚无卡片”，不能据此重写或重报缺口。保留可核验的原作者与审核记录，只对缺失、失效或语言依据不足的部分补做。临时目录可能被 Git 忽略，任务已给出的脚本路径应直接检查；默认 `rg` 搜不到不证明脚本不存在。

创建作者子代理时，显式传入 `model: "gpt-6-astra"`、`reasoning_effort: "low"`、`fork_turns: "none"`，在任务里提供上述最小材料。复用前核对原配置：`followup_task` 不能改变模型或推理强度。作者交稿后可以继续其他独占编写批次，不转任审核子代理。审核由主代理使用当前配置承担，不再分派第二轮审核代理。

先从每类表达挑选一个小批，覆盖普通词、不规则词及明显的词义边界。协调者读实际成句并反馈后，再安排下一批。批量大小按已观察到的质量调整：扩写一旦出现通用后项、占位翻译、全假名省事稿或报告与产物不符，就暂停该作者扩写、缩小任务、整批返修；不要只重复“请认真”后继续派更大的清单。

不同编写分片可以并行推进；主代理审核已交付批次时，作者可继续其他独占分片。同一时刻一个数据文件只有一个写入负责人：作者明确停止写入后交主代理，主代理完成逐卡审核、检查与版本封存后接入。返修退给作者时，主代理先停写，收到新交付后重新审受影响内容。

只登记将立即启动的具体工作，登记成功后实际派发并核对运行状态。状态文件中的 owner 不是运行句柄；派发失败或负责人已经结束时，保留产物和历史，显式交接给符合配置的可用代理。不要把已登记但未启动的批次算作正在并行执行。

### 协议 2：先提交，再验收

当前实现是任务目录内的 `pipeline.mjs`（本轮位于 `work/actions-20260918/pipeline.mjs`），可复用快照与串行执行工具在本 skill 的 `scripts/delivery-store.mjs`、`scripts/checked-steps.mjs`。新任务应在自己的任务目录适配流水线，不把本轮路径当成固定长期存储。新批次优先 `assign-author --protocol 2`；已有批次由协调者确认原负责人停写后显式 `enable-delivery --batch lane/NN --actor root`，不会自动升级。旧批次保持 `freeze-*` 兼容，协议 2 则禁止它们绕过提交与验收。

作者或审核者把检查命令写成 JSON `steps`（每步明确 `executable` 与字符串 `args`，不经 shell）及本批 `outputs`，运行 `run-checks --batch lane/NN --agent NAME --plan lane/NN.checks.json`。工具先撤销旧成功证据，再串行运行；任何非零退出或输入文件在检查中变化都会失败，之后不能提交旧产物。检查后改稿也会使证据失效。

检查计划示例（从任务目录运行；把脚本路径替换为真实绝对路径）：

```json
{
  "outputs": ["lane/00.review-check.md", "lane/00.review-readings.json"],
  "steps": [
    {"executable": "node", "args": ["/absolute/skill/scripts/card-workbench.mjs", "check", "--project", "/absolute/project", "--input", "lane/00.cards.json", "--assignment", "lane/00.assignment.json", "--output", "lane/00.review-check.md"]},
    {"executable": "uv", "args": ["run", "--no-project", "--with", "fugashi[unidic-lite]", "python", "/absolute/skill/scripts/reading-audit.py", "--project", "/absolute/project", "--input", "lane/00.cards.json", "--output", "lane/00.review-readings.json"]}
  ]
}
```

先生成内容，再运行上述检查。候选判读需修改审核报告时，修改后再运行检查绑定最终文件；仅重跑扫描或更新时间戳不能满足“交接后有新报告”的要求。未改卡片的复审可以保留原卡，但须写明本轮实际核验的具体证据。

`submit-author`／`submit-review` 必须携带 `run-checks` 成功返回的 `--revision`；它们验证工作稿、报告与检查证据，创建包含最终字节的快照和 SHA-256 receipt，释放 owner 并停在 submitted 状态。协调者确认代理已停写、实际内容已读，再用 **返回的 `submission.delivery.receipt` 和 submitted revision** 执行 `accept-author`／`accept-review --actor root --receipt ... --revision ...`。验收拒绝旧 receipt、旧 revision、工作文件晚写或快照漂移；不能把“提交成功”计为“已审核”。

返修用 `reject-submission --receipt ... --reason ...` 保留旧提交并返回原负责人，新提交生成新 receipt。已接受稿件则按既有 reopen 流程进入新轮次。快照包含作者当时的原稿；审核者可以合法修改工作稿，但不能把修改后的稿伪称为旧作者快照。旧 reviewed 批次的 `seal-reviewed` 只封存当前已冻结的审核文件，不补造作者历史。

快照位于任务目录的 `deliveries/<batch>/rev-<revision>-<phase>-<uuid>/`；工具先完整写入临时目录，再原子重命名并登记状态。提交失败不会留下可验收的半成品，重试使用新目录，不覆盖旧快照。接入读取 `readDelivery` 验证后返回的同一份字节，不在验证后重新读取易变化的工作稿。共享目录的 owner 和 actor 不是权限系统：无法阻止绕过工具的直接写入，但此类变动不得通过验收或接入校验。

作者任务可按下列信息组织，不要求照抄措辞：

> 读取仓库内 skill 与所需专项规则。按指定只读清单逐条制作，仅写指定内容文件及临时报告；固定词义／形式，每卡显式保存实际场景、句段和译文，状态为 draft。用当前活用器还原整句，执行精确清单检查和读音对照，列出具体未决项。完成本批后停止写入，不自行扩写其他文件或再次委派。

主代理接管审核时，保留原作者快照，以实际主代理身份登记 reviewer。作者与主代理的身份可以满足现有作者／审核者分离校验，无需为流水线虚构审核子代理；主代理自写自审的任务应如实记录，不通过另取代理名伪装独审。旧子代理的真实审核记录保留为历史，不因流程变化改写身份。

## 3. 检查产物，再决定返修或批准

先跑分片的 `check --assignment`，协调者同时核对最初保存的要求没有变化；不要接受作者改用 `--forms` 后声称精确覆盖通过。形式数相等不能证明每个词义／形式都完成。新增任务还应与旧卡 ID 检查交集；工具对同 ID 的稿件可能只报告 `replaced`，不等于授权覆盖旧卡，只有明确的修订任务才按约定替换。合并时再做一次总范围的精确检查，防止分片间重复、漏项或误覆盖旧卡。

在交给审核者前先运行 `scripts/review-preflight.mjs`。它把可机械确定的结构、字段、范围、哈希、模板和报告过期问题挡在审核队列外，并把肯否、过去、完成／准备、授受和语体等仍需语言判断的卡列为 attention。预检输出是筛选证据，不是自然度结论；审核者仍须逐句阅读 attention 以外的每张卡。冻结命令会再次运行预检，不能用旧报告或手动复制绕过。

语言审核由主代理覆盖本批每张实际生成句：`before + resolveUsageCard(card).target + after`，连同场景、译文和读音一起读。作者自审后直接进入主代理审核，不增加审核子代理。按小批逐句记录具体判断，亲自处理争议与返修；不能把抽查、结构检查或作者自审摘要写成全批语言通过。主代理编写的部分明确标为自审。

依据[完整句审核](editorial-review.md)和表达族专项规则，分开处理：

- **结构或范围错误**：缺卡、越界、重复、错词义、目标槽外泄露答案等，修复后重新检查，不降低校验要求。
- **明确语言错误**：不通顺、前后无真实关系、时态／否定错误、原词义漂移、译文遗漏或添加事件、注音错误，按固定配对返修。
- **措辞建议**：可以改善但不代表原句错误，报告与实质错误区分。
- **未决配对**：记录卡片 ID、当前完整句、疑点、尝试和证据，不标为 approved，也不藏进“已完成”数量。

逐项判读 `reading-audit.py` 的候选。词典可能把合法异读、数字音变或派生词分错；不能自动替换，也不能把候选数当错误数。改写日语后同步译文、读音和必要的 ruby 分段，再复读实际结果。抽查页面的挖空与答后显示，用真实组件确认注音分界，不用另一套预览渲染规则代替。

报告对应最终文件：至少记录实际配对数、审核状态、未决项和校验结果；大批或多轮返修保留原稿、实质前后差异及最终文件指纹。对仅有格式／注音拆段的变化另行计数，不把“改过多少卡”当模型错误率。作者修改了最后一句，旧的全量报告也不能继续被称为该文件的最终审核。

多轮交接时，给每张卡保存 `id`、实际审阅的完整句、状态、具体理由和内容指纹。指纹统一取源卡对象 `JSON.stringify(card)` 的 SHA-256，不混入文件名、报告行或辅助字段；接入前重算并拒收未匹配的记录。旧通过结论只有在卡片内容未变且原语言审核确实覆盖它时才能沿用。不能只刷新报告里的句子与指纹却保留旧错误理由，也不能把“没有列在错误表”自动展开为全批语言通过。

生成或返修报告的命令失败后，不继续冻结磁盘上的旧报告。先检查命令退出状态，再读取最终产物，核对逐卡理由和读音候选判读实际已经写入；按卡片 ID 修改，避免数组位置变化将译文写到另一张。批内重复的通用理由应作为待复核提示，不能仅凭理由长度、含有句子字符串或 hash 匹配认定已逐卡审核。

协调者须核对报告与实稿：若标为通过的批次仍有占位场景、释义拼接译文、全形共用而肯否冲突的句段，撤销受影响批次的通过结论并实质复审。同一个文件的复审只交给一个负责人；已结束代理的新工作须用能启动新一轮的任务分派，单纯留言不是正在执行。等待前核实代理确实运行，空闲时推进清单核对、返修或接入准备。

## 4. 处理语法与出题适用性的边界

优先核实可靠日语教材、词典或语言研究中的具体义项和完整上下文。同形的可能／尊敬／受身，普通并行／逆接／渐变，动作过程／完成后状态，不能互相背书。实用例可以证明某读法存在，不能单凭一例就声称频率高；搜索不到也不能证明语法不存在。

把结论分成“当前句可修好”“用法自然但课程说明需扩展”“当前固定配对暂缺合适用例”。有自然读法时不要因初稿差、旧中文概括或笼统词类标签整词删除。扩展依据是实际用法与教学价值，不能为了填满数量改词义或弱化语言标准；适用性调整仍逐配对留证。

**反复重写失败，触发该精确配对的适用性复审。** 已换过不同合理场景，仍出现同一搭配或语义问题；修好句子必须换词义、换目标形式或靠中文补出日语没有的意思；主代理复核后仍无法给出适合教学的自然例句——满足这些情况时，暂缓该词义／形式的常规出题，保留构形识别、失败稿、逐次尝试和限制理由。取得能解决实质疑点的可靠用例后再逐对恢复。只有检索无结果、存在更常用说法或同一坏句被重复审阅，不足以作为限制依据；新用义尚有未核验线索时单列开放未决，不将整批未决自动转为暂缓。

适用性发生变化后，旧批次清单和封存是历史证据，不能在新许可下伪称仍全部可解析。保留旧清单与快照，另存新有效要求，逐对证明“原要求＝当前已覆盖＋开放未决＋暂缓”；三者不相交。不要修改原始清单哈希或删除未通过稿来制造覆盖完成。

用户已明确本项目课程可以扩展，不把参考教材或既有释义限定为唯一用义。当前形式下的自然用法可由协调者核实并补充说明、例句与相关验证，无须为每个用法重复确认。新增无关课程或重做教学路线仍按实际任务范围处理。本 skill 不额外设置逐卡用户确认或发布审批要求。

调整许可时由协调者统一处理，避免作者拿到的活用结果在审核途中失效：

- 保留原形态构造及完整词形识别支持，除非发现另有构形错误；“暂不作为常规题”不等于“日语不能这样说”。
- 按具体词义／形式记录理由、审核版本与前后配对差异；先保存暂缓草稿，再从可接入集合中移出。
- 重新从项目推导要求并发出更新后的分片清单，保留旧清单及变化原因，不以最终稿反推需要多少卡。
- 核对课程说明、题目的表达作用与卡片采用的用义一致，不让界面讲条件而卡片只练反复。

## 5. 接入与验证

对应批次的写入负责人交接后，协调者再次核对实际数据与审核报告，再将通过的卡标为 `approved`，接入内容目录与 `USAGE_CARDS`。没有核准的配对不能因“先上线再说”混入；也不要把尚未整合的文件计为网站可见内容。

复核撤销已接入卡的批准时，分别核对工作账本、发布候选、产品目录和部署版本。重开批次不会自动撤回产品里的旧卡；须把撤销项移出候选和产品，更新未决集合及说明，并完成相应验证。未封存的整批数量也不能当作语言错误数。汇报同时标明发布快照与本轮审核状态，不能拿上次发布文档的数字覆盖当前撤销决定。

发布候选须对全部纳入批次运行当前预检，包括沿用旧批准的批次；旧快照的完整性不等于满足更新后的审核标准。预检失败须实质复读相应内容或理由，不能用拼入 ID、原句、目标与通用判断的长理由消除提示。负责人仍在运行时不得冻结；若误冻，保留该快照、撤销验收并在明确停写后重审，不用旧快照覆盖尚在返修的工作稿。

对照原卡快照，确认未获授权修改的旧内容逐对象保持不变。分批接入时保留已有覆盖基线，并准确登记本次批准的新增集合；整个阶段补齐前不宣称逐词完整覆盖。新增完整覆盖的阶段应加入项目审计和相关测试，要求来自当前课程、词库与适用性；固定总数仅用于报告，不代替集合相等验证。保留旧测试基线，显式列出审核批准的变更，不重新生成一份“恰好通过”的历史快照。

按改动运行必要检查，避免扩大成无关耗时审计：

| 改动 | 验证重点 |
| --- | --- |
| 卡片或接入 | 分片与合并的精确清单检查、`npm run audit:usage`、相关内容测试；实际显示与注音抽查；受影响的类型检查、lint、构建 |
| 适用性、课程或选题 | 再跑 `npm run audit:eligibility`、`npm run simulate:perfect`、`npm run simulate:mixed` 及相关回归 |
| 诊断或计分 | 验证实际受影响的整题／拆步归因、独立与辅助计分及完整词形识别；按项目要求选择扩展审计 |
| 仅 skill 或说明 | skill 校验、引用与路径检查；脚本迁移或变动时运行真实命令验证，不为文档改动重跑全部学习模拟 |

课程验收不仅检查总题数：检查每个课程形式、首次教学的知识点和覆盖切面仍有题。适用性审计的原始注册池可能是不带语义筛选的基线，要把本轮真实变更前后题池另行比较。

对退出题池的旧复测目标验证两种情况：仍有同路径词时继续保留待复测；已无同路径题时暂停该义务、保留历史，不凭空增加独立答对或掌握度，也不能反复出无关题补空缺。查看审计的 `retestPaths` 逐项目数据，不只看汇总桶数。全对与混合路线都要检查完成状态，重复风险指标与真实残余复习如实报告，不能把某指标为零说成永不重复。

## 6. 收口与迭代

交付说明给出：本次有效要求、原有覆盖、新增与暂缓数量、剩余缺口、实际接入总数、检查结果和未解决事项。分清“已写草稿”“已审核”“已接入”“已发布”，不混用这些状态。

把反复出现、会改变下次决策的问题写进本仓库 skill；一般规则留在入口，专项语法放在引用文件。不要把每个失败例句堆成禁词表。较大的流程改动可以安排独立小批试作：只给真实任务、skill和必要原材料，不提前泄露预期答案；输出放临时目录，协调者检查实际产物后再迭代。试作不会自动进入题库。

批次清单、原稿、字典差异和试作默认留在任务临时目录；仓库保存可维护的内容、工具、规则和必要的汇总复核文档。个人进度备份、机器缓存和一次性完整工具日志不随 skill 入库。

完成内容制作不自动提交、推送或部署。有用户相应授权时，继续按仓库 `docs/publishing.md` 执行既有流程并核对结果，不另换托管平台或重复请求已有许可。skill源码可以随Git仓库版本管理；它不属于网站运行时资源。
