# 完整句审核要点

编写和审稿时都要看 `before + 活用器实际答案 + after`，不要只读中文，也不要只确认答案字符串合法。下面的检查针对活用道场的构形题，不要求所有语法教材都采用同一题型。

## 先定用法，再写短场景

按任务选择常见且语义适合的词。扩充卡片时优先查看未覆盖的词义／形式对，不因为清单第一项是「読む」就所有题都使用它。不同词的角色、助词和对象不能从同一模板机械替换。

短场景提供理解所需的最少背景；不用再讲一次构形步骤。例如：

- 空泛：谈论访客上门与住户的生活安排。
- 具体：昨天只想独自休息，不愿有人上门。

场景本身可以交代时间或人物，即使日语句省略它们；问题在于语义冲突，不是要求所有背景都逐字出现在例句中。

## 同一词的多种基础变化

共用人物背景不等于复用整句前缀。逐词连看全部生成结果，而不是只检查每种形式的一张代表卡：

- 「明日、駅へ【行った】」不能靠中文“昨天去了车站”修复。时间词应与本句谓词一致；过去句要改前文，译文也逐句对应。
- 「部屋に入り、靴を【脱いで】。」缺少后项。给て形写有实际联系的后续动作，如「靴を【脱いで】、家に入りました。」；不要所有动词都接“然后休息”。
- 译文不能省掉日语已有的关键时间、地点、对象，也不能把「取らない」写成“拿不了”。中文场景不是“礼貌说明没有做＋动词”一类程序拼接句。
- 搭配按词义选择：植物枯萎通常不用「死ぬ」；固定为死ぬ的任务可另选自然的动物或虚构游戏情境。不要用“死了，春天又发芽”拼接两个互相冲突的事件。
- 形容词不全表示程度，不能统一译成“很＋形容词”；「必要だ」可译“有必要／是必需的”。指人不能机械用「これは」介绍；用「この人は」等合适指示语。
- な形容词「に」并不总是动作方式。需要状态变化可用「有名になる」「暇になる」等真实搭配；若任务是形容词副词形，不以「危険にさらされる」等名词＋格助词伪装形容词变化。场景随真实用途写，不统称“以……方式处理”。

这些例子用于识别批量生成失误，不要求各卡采用同一个修复模板。每张卡保持简单、自然、完整即可，无需强行增加原因从句。

## 正文与注音

`text` 是学习者阅读的正文，`reading` 才是辅助读音。使用常用汉字和自然的送假名；不要把「彼は昨日、授業に」写成「かれはきのうじゅぎょうに」来免填读音。应写成：

```js
{text: '彼は昨日、授業に', reading: 'かれはきのう、じゅぎょうに'}
```

整句书写统一，不能只把开头一个词换成汉字。助词、助动词、「ください」「ゆっくり」「かばん」等自然假名写法及片假名外来词照常保留，不追求汉字比例。遇到「会った／あった」「橋／箸」等同音词，用完整句和译文确认，不做脱离语境的读音替换。

读音保留与正文对应的标点；逗号两侧可能都是汉字，省略读音里的逗号会丢失注音分界。检查实际 ruby 是否把「昨日」注成「きのう」、把「授業」注成「じゅぎょう」，不能只确认“句段有 reading”。难以对齐时，把句段拆成带准确读音的词和自然假名段，不猜测汉字边界。

分界假名也可能出现在汉字读音内部，例如「昨日の」读作「きのうの」。这种句段可显式写成 `{text: '昨日', reading: 'きのう'}` 与后续 `{text: 'の部屋は', reading: 'のへやは'}`，避免把「昨日」误注为「き」。

### 注音复核

先从词义和句法判断读法，再看已填的注音。重点核对同形多音词、独立词与助数词、复合词、数字和连浊；不要按单字最熟悉的音读拼接。例如表格的「表」是「ひょう」，表面义才可能是「おもて」；「隣の人」是「ひと」，不能套用人数的「にん」；「道順」是「みちじゅん」，「工具」是「こうぐ」。具体读法应查词条用义，而不只是确认字典里存在这个读音。

批量对照使用完整句和词典的假名书写字段（UniDic 的 `kana`），不把发音字段中的长音或助词实际发音直接抄作书面假名。对照结果要连同 `senseId`、目标形式与译文审读：如「出る」的使役「出させる」读「でさせる」，不能被分词器按另一个动词「出す」的「ださせる」覆盖。「私」的「わたし／わたくし」等合法异读也不能一律替换成模型首选。

改了正文要同时重审该句段的 `reading`；曾有「舌がしびれました」仍带着旧句「ぜんぶたべました」的读音。结构校验能阻止假名和送假名不匹配，却无法区分「表（ひょう／おもて）」或「黙る（だまる）」与另一个词的读音。最后检查实际显示的 ruby 与数字读音，记录已修项和保留异读的理由。不要把“词典对照无差异”或“结构检查通过”称为语义复核通过。

复核来源示例：[表](https://kotobank.jp/word/表-7902)、[道順](https://kotobank.jp/word/道順-638497)、[雨具](https://kotobank.jp/word/雨具-426931)（小学館《デジタル大辞泉》）；[悪口](https://www.kanjipedia.jp/kotoba/0000049000)同时认可「わるくち／わるぐち」，应保留合法异读。

## 容易漏掉的区别

| 检查点 | 需要判断的内容 |
| --- | --- |
| 过去与完成 | 「読んだ」可译“读了”，不自动增添“全部读完”；确需读完的例句可明确「最後まで」。 |
| 普通否定与能力否定 | 「読まなかった」不能无条件译成“没能读”；能力不足需与本题目标及句子中的可能形式相符。 |
| 否定与禁止 | 本课练陈述性否定时，「取らない」译“不拿”，不自动译成“不要拿”。提醒或禁止也许能在其他语境成立，但不能替代当前课程用义。 |
| 愿望与事实 | 「たい」及其过去形不证明动作实际发生；不把“曾想尝试”写成“已经尝试”。 |
| 双重否定 | 在目标「教えてもらわない」后接「つもりはない」会再否定一次，不能仍译成“不打算请人教”。检查全部尾部。 |
| 主语与受益者 | 分清谁做、谁接受帮助、谁受到影响、谁允许谁行动；直接向同事请求帮助时，不把「同僚に」随意加成第三方动作关系。 |
| 词义与否定方向 | 先逐字理解实际目标，再对照译文。「忘れなくてもいい」不能表达“不用记住”；「教えてこない」不能译成“不来问”。不要按想表达的中文反推一个意思不同的原词。 |
| 课程用义 | 同样的目标字符串可进入不同结构。本课若练同一主体的同时动作，「来つつある」的渐变用法不能替代「作業をしつつ話す」；审核需同时看项目给定的目标含义。 |
| 宾语与助词 | 「荷造りを手伝う」可表达帮忙打包；「箱を手伝う」不能表达帮忙搬箱子。「する」也不能接任意名词来表示“处理”：用「機械の修理をする」，不能用「機械をする」表示修机器。命令原地等候需检查「そこで待て」的地点助词。 |
| 施事与语体 | 「コーチは学生たちを泳ぎました」把自动词误当使役；一起游泳应用「学生たちと」。礼貌词尾不表示动作本身“礼貌地”进行，译文不要从「ました」增加“礼貌地”或“表示已经”。 |
| 接续关系 | 「高くて」不自动表达“贵但是……”；并列、原因、条件、让步要与完整句一致。 |
| 目标之外的变化 | 如果要求整个否定形式，答案已含「ない」就不要在槽后重复写「ない」。给单纯过去题加「ら」会使整句成为条件表达；只有刻意采用该语境并确认无误导时才这样写，通常优先简单陈述。 |
| 方向与时间视点 | 「ていく／てくる」明确离开／返回的参照点或持续发展的时间起点，不能把「ていた」任意替换成「ていった」。 |
| 语体 | 「ておる／とる」不是任何场景下都通用的日常礼貌表达；选择适合的说话人、引用或语体，并避免不可靠的地方方言拼接。 |

这些是检查维度，不是模板，也不保证表内某个词适合当前任务的全部目标形式。

## 从稿件到可展示内容

1. 独立读日语完整句：谓词与对象是否自然？有没有「寝て、早く寝なさい」式重复动作？句尾是否真正结束或接上合理后项？有没有同一位置重复否定、助词或接续？
2. 对照目标：仍是要求的完整变化吗？题库认可这个词义／形式对吗？句中的用义是否符合课程本题目标，而非另一种合法结构？不要用相近表达代替目标，或靠 UI 判分接受某变体就假定句中所有变体语用完全相同。
3. 对照场景与译文：否定的对象、愿望主体、施事／受益者和时间一致吗？译文是否擅自增加“终于、已经、没能、全部、再也”等信息？
4. 逐段核对汉字读音，不把拼写合法当成读音正确。例如「胃」与「胸」不能混用读音；助词写法、促音、长音及专名要与原句对应。
5. 检查正面：空格覆盖完整目标；目标读音、完整译文和解释只属于答后内容。槽外保留的文字不能重复答案或替用户完成目标的一部分。
6. 用脚本核对结构及批次范围，查看脚本拼出的整句，再由审核者批准。审稿报告用卡片 ID、完整句和具体原因定位问题，区分明确错误与措辞建议；修订建议应保持分配的形式和词类。不要仅按问题条目数统计受影响卡片。没有合适内容时保留明确的未完成项，说明是哪一个词义／形式及什么问题，不能把它混入已审核计数。

修订后重新生成并阅读最终内容，尤其使用过映射、替换或共享片段的稿件。报告说“已修正”不代表最终卡片已变：检查是否仍保留旧场景、是否只改了日语而没改译文、是否产生“孩子们孩子们”之类重复。用最终卡片 ID 和实际修订前后文本记录证据，不用结构校验的 `issues: []` 充当语言审核结论。
